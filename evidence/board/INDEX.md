## 说明（为什么基准从 LBA 1000 改成 LBA 8192）

原计划按手册初稿读 **LBA 1000**。但实测这张卡的分区**从物理扇区 8192 开始**，因此
物理 LBA 1000 落在「MBR 之后、分区之前」的未分配空隙里 —— **读出来是 512 个 `0x00`**。
两边都全零时，"逐字节比对"几乎失去证明力（数据通路坏成常数 0 也会"通过"）。
改用**分区首扇区（FAT32 DBR）**做基准，内容非零且一眼可辨。

两个容易踩的概念，留档备查：

- FPGA 的 LBA = **从整张卡开头算的物理块号**（SDHC 块地址；SDSC 由 `sd_sector_reader` 内部左移 9 位）。
- Windows 的**卷句柄（`\\.\G:`）偏移从分区开头算**，所以卷偏移 0 == 物理 LBA 8192，**不是** LBA 0。
  读物理 LBA 1000 需要「物理磁盘」句柄（`\\.\PhysicalDrive2`，**要管理员权限**，本次未提权）
  或 HxD 的「打开物理磁盘」。用 `\\.\G:` 偏移 512000 读到的**不是** LBA 1000（那是分区内的另一个位置）。
