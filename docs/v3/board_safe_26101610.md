# 26101610：BASE 只显示 EMERGENCY EXIT 的本地排查

本次用户实测的是 `SafeVision_BASE_9d40698.bit`：LED4 常亮，KEY2 后 LED3 短亮，KEY3/4 无可见变化，TF 图片没有显示。用户确认没有串口连接，暂不确定卡上具体文件名。本轮只更新本地，不上传 GitHub。

现有证据不能确定这块板此次停在 SD 初始化、目录、图片还是 SDRAM 回读。 之前的 113 项正向测试、28 项负控及全角 STA 是离线证据；此次硬件失败已经说明它们不能替代板测。26101610 加入真实等待时间修正和无需串口的屏幕诊断，后续必须读取新画面的数字后再判断物理故障。厂商加密 SDRAM 内部和实际电气仍未由自编模型证明。

## 按键和灯的真实含义

依据 HX4S20 开发板手册的管脚表及当前 ADC：

| 板上标号 | 管脚 | 当前用途 |
|---|---|---|
| KEY1 | A2 | 全局复位，低有效 |
| KEY2 | B2 | 松开时下一张；未就绪或系统 SAFE 时请求有限恢复 |
| KEY3 | B1 | 应急，按住有效；已经 SAFE 时画面可能无明显变化 |
| KEY4 | C1 | 松开时切换自动轮播；缓存未齐时不播放 |
| LED1 | A4 | 四张图同时通过加载和逐行回读校验 |
| LED2 | A3 | 音画转场忙 |
| LED3 | C10 | 恢复流程忙 |
| LED4 | B12 | SAFE，包括启动未就绪、应急、恢复和故障 |

因此，LED4 单独亮并不说明 KEY3 卡住，也不能证明 TF 卡或 SDRAM 哪一个损坏。恢复忙的短亮说明 KEY2 的输入确实产生了恢复动作；没有返回成功仍需查看错误字段。恢复最多三次，失败后不会无限重试；继续试验前可用 KEY1 开始新一轮。

## 已复现并修改的问题

1. D63，跨层超时不一致。 REF=50MHz 时，扇区读取器允许等待数据 token 达到 10000000 拍，即 200ms；旧顶层给帧写入器的 GAP_TIMEOUT 只有 200000 个 MEM50 时钟，即 4ms。SD/FAT 合法等待尚未到期时，写入器已经宣布图像截断。新顶层将像素断流限制改为 25000000 拍，即 500ms，与外层写入无进展限制一致。所有 CRC、帧像素数和地址校验保留，不以延长总帧时间代替无进展检测。
2. D64，缓存已齐后的 SAFE 无法用 KEY2 恢复。 原控制器只看应急键或 `!cached`；监督器故障锁存后，`cached=1` 且转场被 SAFE 门控，KEY2 既不换图也不恢复。板级显式启用 `system_safe` 输入作为恢复条件；通用默认行为保留。FATAL 与三次上限仍由恢复控制器执行。
3. D65，SAFE 隐藏了排查所需的信息。 新增只读状态快照，包含 SD 的命令序号/R1、文件状态/原因、sink 错误、缓存批准、真实回读 CRC 和恢复状态。REF/MEM 先分别完整跨到 SYS，再由已稳定的握手快照在 PIX 帧边界锁存；不改变正常媒体数据。新增跨域路径使用单独的 8ns bundled-data 约束，首级同步器例外和实际对象命中仍受审计。

这些是代码中可复现的问题。没有该板的新诊断值，不能把 D63 或历史 SDRAM 相位问题直接写成此次唯一根因。未改动队友遗留顶层、官方加密 IP、管脚和 V3 的 MEM50/+8ns 配置。

## 新画面怎么读

所有数字为十六进制；在 SAFE/加载阶段显示四行白色诊断文字，应急文字和箭头继续存在。ID 应为 `26101610`。

```text
ID 26101610 P 8/7 E 00/00 F 00
SD 4 R1 00 M C S 1/00 C 0/0 K 0 R 0 T 0
RX 00123456 W 25800 ROW 1E0
BAD 00000000 EXP 00000000 GOT 00000000
```

这是格式示例，不是本次实测记录；数值会随加载变化。SRC/CRC 数值仅是本板真实生产通路的观测，不能拿示例代替观测。

| 字段 | 含义 |
|---|---|
| P a/b | SD/BMP 状态 / 失败阶段 |
| E xx/yy | SD/BMP 原始错误码 / 细分码 |
| F xx | 监督器锁存的故障码，可能与 E 不同 |
| SD、R1 | 初始化命令序号、最后的卡响应；序号0/1/2/3/4对应 CMD0/CMD8/CMD55/ACMD41/CMD58 |
| M | bit3=SDRAM初始化，bit2=适配器初始化，bit1=回读错误，bit0=适配/总线错误；正常初始化后通常为 C |
| S a/bb | 像素 sink 状态 / sink 错误码 |
| C a/b | 文件加载有效位图 / 内存校验批准位图；两者都为 F 才算四图就绪 |
| K | 消抖后的应急键；松开0、按住1，可检验 KEY3 |
| R、T | 恢复状态、已经尝试次数；R=4为等待自检，R=5为失败锁定 |
| RX | 实际消耗的卡扇区字节累计，含目录/FAT，不是 SPI 空轮询 |
| W、ROW | 本次图像已接受的32位字 / 已回读行；一张完成为25800 / 1E0 |
| BAD、EXP、GOT | 回读失败地址、源签名、实际回读签名；未出错时0本身不表示已经验证 |

P 状态：0空闲、1初始化、2 MBR、3 BPB、4扫描、5索引、6选图、7就绪、8流式加载、9提交、A错误、B初始化重试、C拒绝排空、D清理。失败阶段1初始化、2 MBR、3 BPB、4目录、5索引、6选图、7图像流、8提交。

| 新画面的组合 | 下一步依据 |
|---|---|
| P=A/1，E=01/21 或 R1 长期 FF | 卡未给出有效初始化响应；检查插卡、供电、接触，再依据 SD 序号区分命令 |
| P=A/2 或 A/3，细分31/32 | MBR/BPB/FAT32 格式不满足当前解析器；不能据此直接判断内存故障 |
| P=A/5，E=E5 | 当前扫描未找到后续合法命名候选；可能没有足够四张、名称不匹配或前面文件被拒绝 |
| E细分37/38/39/3A/3B | BMP签名、DIB、尺寸、像素格式或完整长度检查失败 |
| C加载不增，S错误03或E=E3/01 | sink图像无效或失败完成；需要结合W、P和卡错误定位，不能把单一03直接认定为断流 |
| M含bit1、S错误F3，EXP与GOT不同 | 真实写入与回读不一致；保留这四行，继续排查 SDRAM 接口、DQM、相位和地址，不关闭 CRC |
| C=F/F仍停SAFE，F非0 | 查监督器锁存原因；现在可用KEY2请求恢复，FATAL仍须KEY1全局复位 |

## 无串口的复测步骤

1. 使用本次本地排查包内的新 BASE 候选；旧 `9d40698` 位流没有这些诊断文字。核对本次索引和哈希，不混用旧发布 ZIP。
2. 原 TF 文件先保留备份。卡为受支持的 MBR/FAT32，根目录准备至少四张 `SV0001.BMP` 至 `SV9999.BMP` 形式的 640×480、24位无压缩 BMP；不是 `0001.BMP`，也不是双扩展名 `.BMP.BMP`。本包提供四张独立测试图，WAV可暂时不放，缺 WAV 会按原设计降级，不应阻止图片。
3. 断电后插卡，上电/下载，松开所有按键。等待20秒，记录四行数字；再短按并松开KEY2，观察 RX/W/ROW、R/T、两缓存位图是否变化。按KEY3时K应变1，松开应回0。
4. 四图通过时 LED1亮、LED4灭并进入正常显示。此时检查KEY2换图及KEY4轮播。任何物理结论以这次真实结果为准。

`safevision/tools/check_v3_tf_files.py` 是只读的主机文件预检查器，可列出名称、BMP头、长度和哈希；`--require-card` 还检查 Windows 驱动器是否报告 FAT32及选中卡根目录。它不格式化、不改名、不写卡，也不能证明原始MBR/FAT簇链或实际读卡电气。检查报告必须输出到卡外目录。
