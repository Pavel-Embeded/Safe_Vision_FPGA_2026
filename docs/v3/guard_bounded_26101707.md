# 保留完整功能的 CRC 校验资源优化

当前完整应用仍采用诊断协议 ID26101704。此次修改保留四槽缓存、逐行 CRC32 校验、独立首错记录和全部媒体功能。

- 计数器依据帧长、行长、突发长和超时上限确定宽度，公开接口仍为原来的32位。
- 最后一个源数据字后不再计算无人使用的下一行地址，避免自底向上最后一行产生负地址。下一帧仍按原接口重新初始化。
- 写入签名与读回校验处于互斥阶段，将 CRC 的输入异或选择放在同一个 CRC32 线性网络之前。仿真检查阶段互斥及帧计数边界。
- 全32位地址合法性判断、CRC失败保护和首错地址/期望值/实际值保持有效。

候选与原始模块逐拍对比：小尺寸53项检查/32次独立CRC对比，完整640×480尺寸1941项检查/1920次独立CRC对比，均正常结束且零错误。比较所有实时公开输出；无效周期的读地址、CRC输出不纳入数据语义比较。

候选综合报告：16900 LUT、13491 DFF、53 RAM9K、13 DSP。该数值仅为综合，不表示布局布线或最终时序通过。此前完整应用布局布线在335个冲突后反复恶化，已停止并标记未验收；不能沿用其时序或生成交付位流。

正式生产模块已经重新通过19个原生正向测试入口，覆盖全部13项V3基础测试、完整尺寸CRC、完整板级顶层、诊断、板级查询、BASE/HD时钟模型和UART命令目录。另有9项正常结束且检出非零错误的语义负向对照，其中计数器减少一位在1024字边界检出6次计数错误、CRC共用阶段取反检出37次错误、关闭读对齐检出60次错误。原始日志和当前输入哈希见 `evidence/v3/guard_bounded_26101707/current/functional.index.json`。

完整尺寸的错误计数器变体触发了测试看门狗，没有正常结束标志，未计入上述9项。现有1024字边界测试能够正常结束并独立检出溢出，没有修改测试断言或放宽看门狗。
