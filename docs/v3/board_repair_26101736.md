## 根因、触发方式与修正

生产入口在 `safevision/platform/anlogic_eg4s20_hx4s20c/rtl/sdram_app_adapter.v`。厂商控制器的实际 App 通路有四字分组行为，不能以理想逐字 SDRAM 模型推断任意起点均正确。

| 触发条件 | 原错误 | 当前修正及证据 |
| --- | --- | --- |
| 单字写、或不足四字的写请求 | 旧两拍方案不能保证控制器产生实际 WRITE | 物理突发至少四拍；主机1 至 16字不变，补拍全部屏蔽 |
| 写起点低两位非零，混合长度及倒序地址 | 只把长度补到四的倍数仍会在物理分组内发生错位；旧25/26写路径6220次比较出错 | 起点向下对齐四字，前导0 至 3拍全掩码，真实数据按偏移装配，尾部再补齐；28同类实板46272次比较零错，并重复启动再次通过 |
| 音频单字访问，或读缓存未命中后从非对齐地址取数 | 旧30旋转读交通6761次比较出错；理想读模型未模拟实际分组行为 | 物理读起点向下对齐，丢弃首尾非请求字，仅把逻辑数据装入16字银行；33同样交通46272次实板比较零错 |
| 逻辑1 至 16字叠加最多3个前导字 | 物理事务可能达到20字，不能用4位物理索引或把全部物理返回写进16字 RAM | 物理计数为5位，物理长4 至 20；逻辑写入下标减去前导，只在有效窗口内落 RAM，完整收齐后才发布 |
| 请求接近物理2M字末端 | 固定预读16字可能越过存储终点 | 逻辑读量裁剪至剩余字数，物理补齐也不越界；四个末端偏移均有正向及破坏负控 |

主机接口、地址单位、时钟域、读回握手及1 至 16字上层请求语义保持不变。真实 byte strobe 继续生效，只有非请求首尾补拍使用全掩码；不是通过丢弃真实像素或音频数据来降低负载。

此外已保留事件原时间戳流水、DIAG同接受沿快照分组、非活动回执银行保持、UART精确超时比较。基础 FAT 优化只作用于 `fat32_cluster_walker`；共享文件系统实际使用 `v3_cluster_walker_ctx`，不能把前者优化声称为后者关键路径修复。后者当前仅有隔离研究，不属于本位流生产改动。

完整 BASE 上板后，两次38项查询分别位于控制测试前、恢复测试后，均读到：

| 项目 | 真实读回 |
| --- | --- |
| STATUS / CACHE | READY(7) / F，四张常驻图均可用 |
| IDLOW / IDHIGH | 00020001 / 00040003，对应文件1、2、3、4 |
| INTEGRITY / PRESENTATION | 0 / 0 |
| VUNDERFLOW / UNDERFLOW / OVERFLOW | 0 / 0 / 0 |
| RECOVERY / RETRIES | 0 / 0 |
| REJECTED / BADERROR / BADID | 0 / 0 / 0 |
| EVENTDROP及UART拒绝/帧/溢出/丢回执计数 | 全部0 |
| FAULT / LEVEL / WAVFALLBACK | 07 / 0 / F |

`07` 是源码登记的 WAV 信息回退，不是图片 CRC 错误。LEVEL=0、四图仍 READY，四路使用ROM后备音；仅靠当前串口不能区分同编号WAV缺失和格式不支持。真实WAV播放及实体音频仍待核验，不应擅自把回退码清零或把LEVEL>=3的故障放行。

实板控制共108次手动提交、8次自动提交，每次均核对实际SLOT与GEN回执，按四图循环及8位generation递增；没有CRC、显示链或音视频欠载错误。最长连续100次手动加4次自动测试耗时213829 ms，发送21624字节，1333个ACK逐一校验校验和、唯一性、对应请求与成功码。另一次完整媒体恢复观察到忙状态、重扫、四图重新校验及返回READY；7561 ms内完成并恢复原轮播设置。

在项目根目录可重新核对已有实板证据：

```powershell
python -B safevision/tools/audit_board_repair_26101736.py --repo . --capture evidence/v3/board_uart_20261017/full_base_26101736_automatic --bit artifacts/board_repair/repair_26101736_674c62e/SafeVision_BASE_674c62e.bit
```
