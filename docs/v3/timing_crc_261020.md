# HD CRC 与按键亮度路径优化记录

本记录对应隔离源提交 `01ef5b423fb2463774d217c26542c2d76be85c2f`。它是保留功能的开发候选；最终 BASE/HD 布线后 STA、位流及实板结果分别验收，不以映射或布局估算代替。

## 触发证据

从保留的合法布线检查点，在新原厂进程重新读取原约束并分析，诊断最小值为 setup −4.535 ns、hold −0.011 ns、recovery +0.422 ns、removal −0.017 ns。最慢路径是 adapter 读 RAM 至 row_guard CRC 状态：24.255 ns，其中连线 17.022 ns、单元 7.233 ns，共 12 级逻辑。该检查点的原构建随后在物理优化阶段崩溃，不能批准位流；新进程只提供定位证据。原始报告和检查点 SHA 保存在 `evidence/v3/handbook_26102001/physical_research147/checkpoint138`。

另一条实际负路径从去抖按键到亮度寄存器，包含百分比加减、饱和选择、转换为有符号 RGB 偏移的串行算术。诊断路径的 setup 为 −2.082 ns。两项优化均针对已有负路径；未改变频率、管脚、外部 I/O 预算或时序例外。

## CRC 结构与时序契约

保留反射 IEEE CRC32 多项式 `EDB88320`、初值 `FFFFFFFF`、行末取反、低字节先输入，以及每行 320 个 32 位字、每次 64 字读回事务。四个常驻槽、坏地址拒绝、逐行签名、批准位、超时和故障恢复接口均保留。

生产接收器的顺序为 WRITE → FLUSH → SWAP → DRAIN。FLUSH 必须等到写缓存排空及 readback 完成，才能返回可接收下一帧的 DRAIN；顶层也仅在 FLUSH 且写缓存排空时发起 readback。因此构建签名与读回校验共享一个 32 位 CRC 状态寄存器。每个源图行、读回行和验证起点仍在原有边沿初始化；吞吐仍为每时钟一个字，所有公共请求、计数和完成边沿保持。媒体复位可中止任意阶段；仿真断言禁止上层在验证阶段同时开新帧或继续构建源签名。

CRC 的线性组合网络改为有界深度的共享异或项。对每个节点传播 GF(2) 掩码，并核对全部 32 个基向量，证明组合变换对全部 2^32 个混合输入等价；另以独立 zlib 核对位序、初末异或约定。原 CRC 函数与原模块作为对照保留，未随候选修改。两种组合形式各完成 1,000,065 次 RTL 对照，正常结束且零错误。独立模块映射从 3 级变为 2 级逻辑；整机效果仍以实际布局布线为准。

原模块与候选的公共输出逐拍比较通过，并完成四槽、正/倒行序、480 行、跨 burst 停顿、坏地址、行末损坏及超时测试。原六组参数化 HD guard 测试也在候选完整回归中重新执行。模型与原始记录见 `physical_research147/crc139`、`crc141`。

## 按键亮度等价重排

保留百分比 0 至 100、步长 5、默认 80，以及 RGB 偏移 `2*pct-100`。加键内部使用 `2*pct-90`，减键使用 `2*pct-110`，再按原边界选择饱和值，消除“先加减 5、再减 100”的串行进位链。128 种百分比位模式乘两个方向共 256 种输入全部等价；原命令、目录绑定、流水时序、手册按键和组合长按五组测试正常通过，比较次数合计 10,605,135。
