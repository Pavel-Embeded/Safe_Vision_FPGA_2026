# 同一完整BASE位流的自动启动与KEY1复位对照

本对照使用已有完整BASE：SafeVision_BASE_03f7ea0.bit，SHA-256 6536ac987a42b2d25bb5e54d404ff8c0c3c89a766014e69eab1cbd2bfe7d51c5。重新从D盘读取指纹相符；用户确认PROGRAM_SRAM成功，并按要求未按KEY1或CONFIG1。未变更TF卡、引脚、功能或生产适配器。

自动启动后COM6完成38个顺序、校验和正确的只读查询，ID=26101714。STATUS=A，CACHE=0，FAULT=03（监督器媒体错误），LEVEL=3，INTEGRITY=1；DIAG04含sink的F3校验失败。源153600字，已通过行数0，首个失败地址0，期望CRC=FCC39D65，实际CRC=02E2E064。UART、BMP拒绝、音视频欠载、恢复次数均0。原始字节与解析见evidence/v3/board_uart_20261017/full14_startup_control_20261017/automatic；RX SHA-256为3aa6c22a2b152ec740a3d379200fbadbd8081a63d8fd24fc941a3c42c8fa3467。

此前同一位流的实际CRC为43F6E7A7，且一次软件恢复后复现同值。本次重下载后CRC变化，说明不能把先前一次运行周期内的确定复现扩展为跨重配置始终同值。这两种CRC均不等于0至1000000个全零32位字的CRC，仍不能仅据此唯一定位具体物理错误。

独立小程序26101716在KEY1复位后两条路径各1024字均通过；但它和完整应用、失败的小程序26101715的映射均不同，因此不能直接据此认定上电复位是唯一根因。下一项必需证据是保持同一完整BASE位流与TF卡，只按KEY1，再读取同一组38项查询。该对照尚在等待用户操作实体按键。未关闭完整性保护或批准坏帧；GitHub不上传。
