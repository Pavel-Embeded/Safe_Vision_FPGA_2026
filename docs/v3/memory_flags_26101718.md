# 26101718：紧凑观测与事件优先级时序修正

完整14程序在重新下载和KEY1对照中均首行CRC失败；新补录官方命令行自动下载16的双向自检，写路径996/1024错误、读路径0错误。随后恢复同一完整14，CRC变为97C7AB20，CACHE仍0。新证据保留原始462/874字节、串口日志、JTAG命令和哈希。不能据此把全部故障归结为唯一上电复位或某块RAM的问题。

本版保持图片、音频、融合、缩放、配置、HUD、CRC拒绝和恢复功能；生产SDRAM适配器与厂商IP不改。被动观测仍捕获首行各320字，并在满窗后冻结。将四个32位逐位OR累加器改为四个非零粘滞位，隔离综合比前方案少166LUT/124DFF。各字任一位非零即置1；满320且标记0才能证明该窗口全零。旧*_or端口名字仅保持装配兼容，现在是对非零谓词取OR，不能把标记1当作原始数据值。

DIAG0更新为26101718；DIAG10/11/12/13为物理读/验证客户端/源接受/实际未掩码写命令窗口的0或1标记，bits31:1必须0。DIAG14各9位仍为源、写、物理读计数；DIAG15 bits23:15仍为客户端计数，DM/状态保持原定义。完整计数仍为DIAG14=05028140，DIAG15计数域00A00000。旧17逐位OR格式与本版不同，分析时必须显式expected-id18。

为解决原HD的pending至fault_level关键路径及SAFE状态路径，事件选择采用互斥的最低位优先平面，错误码、来源、时间戳与等级按该平面并行选择；SAFE把恢复/致命输入留在末级OR。没有增加寄存器、回复或事件延迟。独立参考逐拍核对全部101个公开位、两种毫秒分频，345455次比较零错误；故意去除优先级条件正常结束并检出96850错误，另8192种优先级/等级组合检查通过。隔离综合增加55LUT、不增加DFF；组合后的资源和全部时序仍须重新原生检查，不能把两份独立综合数直接相加当作最终结果。
