# 四项显示功能：接口、操作与验证边界

本目录为开发候选。只有匹配同一源码的 BASE、HD 布局布线、全部时序、功能回归和位流封装全部通过，才可替换板上程序。本轮不上传 GitHub、不写 Flash。

## 1. 左下角启动运行时间

显示 `UP 00000123 s`，表示本次 FPGA 配置开始运行后约 123 秒。计时依据板载 50 MHz 参考时钟，每 50,000,000 个周期加一秒，不依赖显示帧率、读卡速度、播放状态或串口轮询。这里不把电脑开始传输位流的时间算进来；FPGA 能直接计量的是配置完成、逻辑启动后的时间。

`v3_boot_uptime` 仅通过配置初值建立新计时周期。KEY1 复位、媒体恢复、切图均不清零；重新配置 FPGA 或断电会归零。8 位十进制秒数最多显示 99,999,999 秒，随后饱和。参考晶振自身精度决定真实时间误差。

BCD 数字通过确认握手邮箱进入像素时钟域，接收发生在垂直消隐的帧起点，避免同一帧显示一半旧数字、一半新数字。邮箱保持期间数据不变，8 ns 数据飞行约束及映射对象检查随工程生成。SAFE 画面也显示计时。时间字段与已有字形 ROM 共用四拍绘制通路。

## 2. PCM 波形替代音量柱

生产顶层关闭两种旧音量柱，同时关闭左下角输入能量条；音量仍可调整、查询，数值在参数行显示。能量计算保留为内部诊断，不用能量值伪造波形。

右下区域显示实际送往 HDMI 的左声道 PCM 波形。取样点在报警/音乐混合、优先级、音量处理及音频跨时钟 FIFO 之后，使用真实 `pcm_valid`。128 个连续的 48 kHz 采样点约覆盖 2.67 ms，每个采样点占两列，总宽 256 像素。青色线条连接相邻采样值；灰色边框和零线提供位置参照。静音是中心水平线；稳态正弦可能呈稳定波形，不应人为添加跳动。

为了节约资源，显示使用 PCM 的最高 8 位，满刻度约为中心上下各 32 像素。这不改变播放数据；很小的输入可能在显示量化后落在零线。当前显示不执行 FFT、不宣称频谱。双缓冲采集完整窗口后等待帧起点交换；正在显示的缓冲本帧不被写入，监测模块不向音频链施加反压。

## 3. 板载按键与参数回显

常态 KEY2 下一图，KEY3 开关自动播放，KEY4 进入应急；KEY1 为复位。KEY2 与 KEY3 同时按住约两秒打开设置菜单。菜单内短按 KEY2 增加、短按 KEY3 减少，长按 KEY2 切换字段，长按 KEY3 退出。组合按键不会漏发下一图命令。

时间、参数行和波形区域都有固定深色衬底，以免白色图片覆盖白色文字。屏幕顶部参数行持续显示 BRI、CON、SCL、VOL，菜单中也显示选中项目及当前数值。亮度百分比 0 至 100、步长 5、默认 80，映射到 RGB888 有符号偏移 `2*pct-100`；对比度为 Q1.7 系数，64 至 255、步长 8、默认 128。UART 兼容原始有符号亮度偏移，采用该模式时显示正负号，避免把原始偏移误标为百分比。

保留最近邻/双线性输出插值选择、1:1/FIT/1/2/1/4 显示模式、Fade、音量、2/5/10/30 秒轮播、OSD 透明度等菜单项。配置在 KEY1/媒体恢复后保留，重新配置/断电后恢复默认值。菜单和状态层继续经过原有 Alpha 合成，字体和叠加颜色均需检查最终 RGB，不能只看寄存器数值。

## 4. 不同尺寸 BMP 装载与缩放

生产常驻缓存路径支持宽 1 至 1920、高 1 至 1080 的 BMP，24 位 BGR、BI_RGB 无压缩、合法文件长度、支持正高度 bottom-up 和负高度 top-down。按每行 `ceil(width*3/4)*4` 处理填充。零尺寸、超出范围、压缩/位深错误、文件长度溢出或截断均不得发布为有效图片；不是任意编码格式或无限尺寸。

大图装载可能超过原有每文件3秒总时限，因此常驻路径改为3秒无进展超时：消耗输入字节或交付规范像素才算进展，卡死仍会超时。首次装载总预算为60秒，以毫秒常量表达，避免32位周期常量溢出；实际有数据就连续装载，不会固定等待60秒。原有4.9秒恢复等待和失败回SAFE机制不放宽，四幅最大尺寸图片发生重新读卡时可能无法在该恢复窗口内完成，需如实报告SAFE/重试。

每幅图装载时按比例适配 640×480 规范缓存，居中补黑边，完整保留原图、不裁剪。横向最近邻选点为 `floor(dx*W/dw)`，纵向同理；反向存储使用对应反向公式，避免非整数缩放时 top-down 与 bottom-up 差一行。硬件使用逐步减法和有理数累加，不使用通用组合除法。极细长图片的显示尺寸至少为一像素。

一行 RGB565 缓存支持重复输出，以放大小图；丢弃未选中的源行，以缩小大图。输出总是恰好 640×480 个像素，反压期间像素和坐标稳定。四幅规范图片仍常驻 SDRAM，保留行 CRC32、读回校验、坏文件跳过、帧边界提交及跨图 Fade。只有整份输入解析完成且内存校验成功后，文件所属槽才有效。

HDMI 输出仍为 BASE 640×480 或 HD 1280×720。已有 HD FIT 在 960×720 的 4:3 画布中显示规范缓存，因此宽屏原图可能同时存在上下和左右黑边；此版本不宣称宽屏原图能铺满整个 1280×720。HD 输出放大可继续选择双线性插值，但装载阶段的缩小仍为最近邻，不宣称高质量抗混叠滤波。

## 本次实现审查补充

源数据与实际接受的写入数据采用独立的32位采样寄存器进行精确比较，原有行CRC32及完整帧读回核验继续执行。默认通用接口保留原有CRC16行为；生产常驻路径采用更强的精确比较。已加入CRC16碰撞负例，防止等CRC但不同数据被接受。厂商映射审计必须找到彼此独立的32位源数据、32位总线数据和1位错误锁存器；这项检查只检查存在性，不添加时序例外。

FAT32和MBR私有字段仅在完整头部接收后使用。保留必须输出的全部地址/数值精度，对只参与合法性判断的原始字段保存等价的布尔结果；对完整多字节字段共用移位捕获使能。公开结果、错误优先级、握手、复位及重启边沿均通过逐周期对照检查。

缩放器在构造输入行与重放输出行这两个互斥阶段复用行地址与DDA暂存寄存器。首次输入行必须重新初始化DDA暂存值，不能沿用黑边绘制的右边界。修正候选已完成64,403,817次比较，包含独立整数除法坐标参考和完整输出端口边沿核对；失败的先前候选单独保存。

HD缓存的完整CRC32只共享异或子表达式，不改变校验位数、输入吞吐或更新边沿。缓存标签的私有数据由单独复位的有效位控制，只有完整发布后才能命中；公开有效位仍按原规则复位，旧数据不能重新获得使用资格。一般缓存接口已有逐周期和独立像素对照，生产打包路径仍须通过压力回归。

以上属于实现与仿真证据。最终布局、完整Slow/Fast时序、位流、自动SRAM烧录、串口与实体画面验收仍分别记录；开发候选不得作为已验收位流交付。


## 按行分组缓存与资源授权

原打包缓存把八个640像素行分摊到十个512像素存储块，需要额外的跨块寻址和五选一读出。候选改为按行奇偶分组：每个流使用两个RAM32K块，分别保存行0/2及1/3，邻行读出不会争用同一端口。仍保留双流、每流四行、640像素行宽、RGB565精度、两个写入相位和相同输出延迟。

RAM32K与RAM9K是同一物理池的两种配置，一个RAM32K按四个RAM9K等效单元计数，不能当成独立新增容量。四个RAM32K占16/64个等效单元。预计全工程使用62/64，最终以厂商报告与成功布局布线为准。用户2026-10-20明确允许RAM达到器件实际容量；目标仍尽量减少资源，所有物理容量、时序和功能门槛保留。

新布局的对照分别覆盖BASE/HD各8,462,384次比较。所有复位控制边沿都必须一致；像素载荷按原接口约定，在复位释放并完成至少三拍预取后比较。旧纯MUX测试在复位期间也比较了未发布的存储器读口值，这些值依赖物理布局，因此不能作为有效画面。原失败日志保留，新的对照清单明确记录此接口资格条件；有效扫描的完整坐标覆盖没有缩小。新布局已重跑HD FIT、双流八邻点及音频/刷新压力测试，5,529,600个像素比较通过，仍须其他模式、整机回归及全角时序。


## 本轮进一步的等价优化

音频四路环形缓冲保留每路64KiB完整容量；读写指针增加回绕位，由模差计算占用量，删除四份重复计数寄存器。物理地址只取低14位，回绕位不进入SDRAM地址。公共接口旧实现对照2,326,234次、全部15位指针及递推检查4,194,304次通过；完整容量、四路、回绕、反压、刷新、generation和复位均有覆盖。旧寄存计数表示的280算术用例迁移到300，原测试与原记录保留，不能把失去适用条件的用例记为通过。

命令流水用九位参数和统一无效哨兵-256替代重复保存的派生字段，仍核查完整32位输入的所有合法范围、错误码和响应边沿。UART丢弃计数使用33位进位实现相同的32位饱和；不允许计数溢出回零。删除音频回绕位、写指针多走一字、读指针反向、无效参数错误变零的四种负向控制均被测试检出并正常结束。

HD行校验索引中的乘205模512改写为(1-4)*(1+16)*(1+256)，只保留七位减法、五位加法和一位异或。对于全部九位输入结果精确相同；完整32位范围、行对齐与整除判断保留。BASE仍使用原通用行校验实现。此处属于内部寻址运算化简，不减少CRC32位数，不放宽合法地址，也不增加查询延迟。

本提交尚须匹配源码的最终BASE/HD功能回归、成功布局布线、Slow/Fast全部时序及位流封装，才允许自动SRAM下载。原理推导、单元测试或资源表均不替代这些最终验收。


## 正式构建工作目录修正

TD对readmemh相对路径的查找包含“进程启动目录”，单独在Tcl里cd到输出目录不足以避免HDL-5105告警。正式构建现在把TD进程启动目录设为该模式的隔离输出目录，Tcl在读HDL前把六份资产复制到这个目录；不向用户桌面或全局工具目录临时投放文件。位图字形、九位文本描述和命令表仍必须在映射网表中逐位核对，不能用文件存在性代替内容审计。原313的告警日志和BASE负裕量保留为失败证据。


TD前端对字符串参数默认值还会优先在HDL目录查找。仅修正进程启动目录未消除告警，因此增加两个受校验的ROM生成副本，分别与BASE/HD状态模块同目录；编辑源仍唯一为assets/fonts/v3_four_features_text.mem。GUI工程生成时同步这两个副本，源码快照必须逐字节相同，否则拒绝构建。两份副本都进入显式构建哈希，物理输入总数由195变为197。仿真默认文件名、测试资产和RTL逻辑均不变；不得屏蔽HDL-5105告警。


## 布局后寄存器与参数回执

TD打包会把sample_mismatch触发器放入以state命名的物理片，不能用旧独立单元名称是否存在来判定逻辑保留。审计现精确筛选32位源、32位总线和1位故障的逻辑Q网，再对最终布局布线网表沿每个物理Q输出核对65个独立触发器位；同一个物理片内不同Q位允许共存，同一个Q位不得复用为两份采样。真实布局网表基线通过，并检出故障Q缺失、源/总线Q混同和触发器类型错误三个负例。检查不添加时序例外。

bdd_opt与lut4_map是厂商支持但默认参数表隐藏的选项，正式流程直接get_param读回并保存原始文件，禁止把未显示当成默认正确。BASE复用已对照验证的短复位/释放计数器和长等待计数器，保持公共复位、超时、失败优先级和尝试次数的逐周期语义，移除宽超时比较到计数使能的长路径。引脚、时钟周期、外部I/O预算和所有SDC约束字节保持原样。上述更改仍须本提交自己的正式物理和实板验收。
