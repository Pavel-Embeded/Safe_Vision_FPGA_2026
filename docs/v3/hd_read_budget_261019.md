# HD 双图渐变供数修复

本次修复保留手册功能。BASE 的105份HDL逐文件SHA未改变；HD显式选择第10个独立实现 `safevision/rtl/hd/sdram_app_adapter.v`。GUI与命令行均使用同一105份HDL清单，总物理输入185份。未经新一轮时序、位流和实板验收，不能把本源码当作已完成的HD发布版。

## 实际故障与测试缺口

原HD位流 `SafeVision_HD_dcc5fc2.bit` 已通过严格布线时序和40组串口配置，但首次NEXT在32帧双图Fade时停滞。随后查询到视频欠载5296246、音频欠载1736，CRC和完整性计数仍为0。关闭Fade只用于诊断：8次NEXT可完成，视频欠载0，音频历史计数未再增加。完整BASE已重新写入SRAM，60秒观察9次自动提交，列明错误均0。原始字节及下载记录保存在 `evidence/v3/handbook_26101901/board16`。

旧共享总线压力测试仅覆盖HD等比适配。它每3条输出行推进2条源行，无法证明1:1和缩略图模式的瞬时双图吞吐。理想读数据源的完整帧测试可证明像素运算，却不能替代物理应用端口的供数预算。

HD约22.25微秒一行。1:1双图每行须读取两条640像素RGB565源行，即640个32位字，瞬时需求约28.77M字/秒。原16字物理读突发后至少16拍静默，50MHz下理论上限已低于25M字/秒，尚未扣除握手和刷新。BASE每行约31.77微秒，同一任务约20.14M字/秒。该差异与板上BASE正常、HD双图失败一致；模型对照已复现供数不足，实际厂商IP的64字运行仍须另行验证。

## 具体修改及接口约定

- HD两个读缓存bank各由16字扩为64字，匹配行DMA每次64字请求，降低命令间固定静默的开销。同步RAM输出时序及公开端口不变。
- 读数据、头指针、物理/逻辑长度与计数器同步扩宽；物理读取按4字组对齐，并滤去首尾填充字。
- 在2M字物理末端截断预读，禁止地址绕回；写入立即使缓存失效，取消写入后不追加到旧bank。
- 写缓存仍为16字，原字节掩码、写屏障、至少16拍静默、超时隔离、50MHz/+8ns时钟均保留。没有降低视频时钟、关闭Fade或删除缩放模式。
- BASE继续使用原适配器，HD清单只替换对应路径。厂商加密IP文件未改动。

## 验证设计

`hd_read64_sim.json` 的四组地址、握手、稀疏写、掩码、重置、长短响应和物理末端测试由现有独立测试仅更改模块名得到。冻结清单记录原始SHA，审计会反向恢复并核验，防止修改预期值迎合实现。

`hd_stream_budget_sim.json` 新增四种几何及延迟11拍的完整HD扫描：真实PCM环、异步FIFO、共享仲裁、内存控制器、HD适配器、应用端口合同模型共同工作。每个可见像素核对双图8个邻点，四路PCM持续按48kHz补入，音频输出逐样本核对；模型包含刷新阻塞、DQM延迟、4字组与16拍静默检查。所有等待有边界，超时、崩溃和缺少正常结束均失败。

原16字实现作为容量回退负向控制；另故意破坏数据和bank索引，要求测试正常结束且明确报告错误。正式验收只接受无运行时覆盖的当前生产源码正例。研究模型接受4至68字物理读组，是待实板检验的端口假设，不是厂商加密IP仿真，也不证明外部SDRAM电气时序。
