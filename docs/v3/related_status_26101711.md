# 相关时钟状态通道：保留全部查询与完整媒体功能

此次只替换板级 REF50/MEM50 到 SYS100 的连续状态快照。全部状态字段、四图缓存、CRC保护、音视频、恢复及UART命令保留，诊断版本标记更新为26101711。

原实现对204位REF状态和48位MEM状态分别保存一份源端邮箱负载及一份接收端数据，共用请求/应答同步。当前配置中，REF50是系统PLL的参考，MEM50和SYS100来自同一固定PLL；动态配置和动态相移关闭。原生约束由真实PLL参数推导这些相关时钟。

新模块 `v3_related_status_capture` 直接使用源端已有寄存器，通过一层SYS寄存器连续采样。复位清除数据和有效标志，复位后一个SYS采样周期恢复发布。状态仍是完整字的快照；多次串口查询彼此独立，并不是跨查询的原子事务。

此模块只适用于本板已配置的相关时钟，不能用于互不相关的时钟源。SRC寄存器到SYS采样寄存器必须通过普通setup/hold检查，包括重合时钟边沿的hold检查。删除原来两组邮箱8ns datapath-only约束，不给新数据通道增加false path或多周期豁免。其余异步邮箱保留原握手和物理飞行时间约束。

验证包含252位数据的变化、源端多位进位、重合/固定相差的时钟及16个复位时期，另重新运行完整顶层、诊断、板级查询及BASE/HD时钟模型。原始证据和输入哈希位于 `evidence/v3/related_status_26101711`。这些模型不代替真实布线时序，也不覆盖厂商加密IP内部行为。

此前布局显示HD逻辑块打包占用97%，即使LUT总量小于19600仍会拥塞。此次减少重复负载寄存器的实际收益以随附综合报告为准；正式BASE/HD布局布线、所有角点setup/hold/recovery/removal与真实整机上板仍须分别验收。

真实板上已经通过的结果仍限定于临时SDRAM修复自检：60000轮、61440000次比对、零错误。该自检没有HDMI输出，不能据此宣称完整媒体应用已通过。按用户最新要求只更新本地，不上传GitHub。
