# 2026-10-17 SDRAM 读回错位排查

用户实际下载 `SafeVision_MEM50_P8_DIRECT_26101612.bit` 后，COM6 收到完整 190 字节原始报告。SHA-256 为 `6c6e7d318f819d955b3ed30ab7827f85f2751221797ee8b26b32016613ce2c72`。原始字节、带时间戳日志及解码位于 `evidence/v3/board_uart_20261017/m50p8_direct_26101612`。该旧协议没有校验和；不能把可解析当作具有传输检错保证。

```text
SV3-M50P8-DIR
INIT=01 LOCK=01
CFG=0B1 BASE=000000 N=000400
RND=00000001/00000006 PAT=0
W=0400 R=0400 CAP=0400 BAD=03C0
TOT=0000000400
BAD0=00000001:000000 E=A55A3CC3 A=A41B3DCB
```

这是一项真实失败：第 1 轮 mode0，1024 次写入、1024 次读取、1024 次返回，960 个字不符，随后按既有设计停止。INIT/LOCK 为 1 只说明对应状态信号已置位。该测试绕过 TF/FAT、媒体适配器、行 CRC 和显示装配，因此问题可以在直接 SDRAM 应用接口重现；它不能单独确定完整应用所有故障的原因。

首错地址 0 的期望签名是 `A55A3CC3`，实际 `A41B3DCB` 精确对应下一个稀疏地址 `0x000801`（2049），而不是随机翻转的证据。960=64×15，恰好符合每个 16 字突发中有 15 个字发生错位的假设。现有报告没有给出全部错地址和每拍数据，所以“每个突发最后一字正确”仍是待验证推断，不能当作已经观测的事实。请求地址取样、写入对齐、返回数据与有效信号关系都需要继续区分。

## 独立逐拍探针 26101701

新顶层 `sv_v3_read_trace` 保持上一探针的 MEM50MHz、SDRAM +8ns、原厂加密 IP、写读请求、稀疏地址、16 字突发及静默间隔。没有向正式媒体通路应用任何推测性数据移位。它同时统计：

| 字段 | 与第 k 个期望字比较的数据 |
|---|---|
| P | 该 `Sdr_rd_en` 有效边沿前一拍的数据寄存值 |
| C | 该有效边沿当前数据，保持旧探针口径 |
| N | 该有效边沿后一拍的数据 |

`ALIGN P=... C=... N=...` 是各自不符次数，零表示在该轮测试地址/图案内吻合，不表示完整工程验收通过。仍以当前 C 路决定成功/失败；P/N 不会绕过现有比较器。默认六轮，C 路首次失败即停止，因此预计当前故障下只报告第 1 轮。

`T=00..15` 给出 22 个连续 MEM 上升沿的接口原始数据及有效位，索引 02 是第一拍有效返回，00/01 为之前两拍；整个窗口来自复位后首个突发，模式为 0。每个字是厂商应用接口输出，不是 SDRAM 焊盘信号。窗口只保存一次。多轮正常运行时 ALIGN 对应最后轮，T 窗口仍属于第 1 轮，不能跨轮直接比较。

串口为 115200/8N1，固定 694 字节，抬头 `SV3-M50P8-TRACE ID=26101701`，末尾 `DONE`。新协议也没有校验和；主机必须核查完整长度、结构、身份、计数和原始文件指纹。先打开采集，再用 PROGRAM_SRAM 下载；KEY1 可复位当前 SRAM 程序，CONFIG1 会重载 Flash。该探针不输出 HDMI，完整 BASE/HD 源码与功能保留。GitHub 不上传。

独立合成模型分别构造有效信号早一拍、完全对齐、晚一拍，以及一次单比特损坏；模型真实按地址存取并执行字节写掩码。28 项检查逐字节核对四份报告（2776 字节）及 P/C/N 计数、首错与 LED 状态。这些场景检验诊断器能否区分假设，不能替代原厂加密实现或实际芯片。故意把前一拍采样替换成当前拍的负向修改已被独立计数和串口比较拒绝，正常结束并报告非零错误。正向/负向原始日志及指纹见 `evidence/v3/read_trace_26101701/functional.index.json`。
