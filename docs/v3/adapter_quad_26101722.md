# 26101722：完整四拍写突发及保护区诊断

21的一拍DQM实板对照未修复写入，因此不推广该掩码延迟。随后检查TD生成的公开映射网表：cnt4在App写/读连续有效时加一、无效时清零；col_en只在延迟一拍的使能有效且cnt4=3时置位；写列命令还需延迟使能与col_en同时有效。因此1/2/3拍没有WRITE列命令，每完整4拍触发一次。抽取的未修改逻辑单元、原网表SHA与0..33拍控制递推结果保存在evidence/v3/adapter_quad_26101722/mapped_column_evidence；原网表随不可变21诊断包保留。

实验使用单独命名的sdram_app_adapter_fourbeat，仅将physical_words改为向上补齐到4的倍数（1..16→4/8/12/16）。生产适配器保持不变。补拍仍为全掩码，地址连续，不采用一拍DQM延迟，不改厂商IP、PLL或时序约束。接口握手、缓存、刷新间隙和已实板确认的读数据对齐保持原契约。

每轮先以直接16拍写入16个非零相邻保护字，排空后才写1024目标字；读回全部1040字。六图案、两个方向，12轮共12480比较。UART每帧231字节，N/W=1024，R/CAP=1040，TOT最后=12480，TX=5A5AA1A5；两方向DM=0命令计数均1040。任何目标或保护字错误均使BAD非零。实板全零错误之前，只能称候选诊断。

模型采用独立完整四拍提交契约，并非厂商加密IP或电气模型。三场景缩小64+16字，共2880数据比较、8316串口字节核对、97检查；奇偶方向各注入单比特并精确报告。退回旧2拍的负控正常结束1173错误，包含独立数据比较失败；关闭补拍掩码的负控正常结束1175错误，包含相邻保护区失败。突发形状报错单独计入负控，但不能代替数据错误证据。

位流仅在两次原生最终STA的setup/hold/recovery/removal及所有必需约束健康检查通过后生成，并绑定本地源码提交、工具、模型/负控和报告哈希。自动官方BitWriter只下载SRAM，串口先开；不写Flash。诊断无HDMI，完整应用代码保留。待实板结果决定是否把4拍修正合入生产，并重新验证完整BASE/HD。GitHub暂不上传。
