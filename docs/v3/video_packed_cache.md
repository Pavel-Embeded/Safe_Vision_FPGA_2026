# V3 视频缓存、时钟与资源契约

`v3_video_display_core` 的生产实例使用 `PACKED_CACHE=1`；默认值为 0，保留可接受随机 `sx` 的通用缓存。两条路径均保留八邻点输出、完整行 CRC、四行循环缓存及原有单拍缓存读取延迟。最终扫描坐标到 RGB/HS/VS/DE/x/y 的总延迟仍为 21 个像素时钟。

## 十块物理 RAM 的安排

每个视频流存四行，每行 640 个 RGB565 像素，共 2,560 个 16 位位置。五块 `512×16` 双端口 RAM 连续保存这四行；当前和目标视频流共十块。地址为 `(source_row % 4) * 640 + column`，高位选择 RAM，低九位为块内地址。相邻行相距 640，循环回绕时相距 1,920，所以同一列的两个行邻点必然落在不同物理块；最后一行 479 的下邻点钳位到自身。

每块 RAM 只有一个 SYS 写端口和一个 PIX 同步读端口。没有第三端口，也没有假定一次读操作返回不相邻的两个地址。像素端以滑动寄存器保存当前列，同步读取 `sx+1`；最近邻及 HD 的 `0,0,1,2,2,3...` 重复坐标均可保持每拍输出。

该分支要求每段有效行的首个 `sx=0`，随后只能保持或递增一，`sy` 在有效段内不变。空白期 `prepare_valid/prepare_sy` 提供下一有效源行，至少预热三拍。违反契约会产生粘滞故障并由整机进入安全画面。通用默认分支没有此单调坐标限制。

## 相关时钟串行写入

生产 MEM50 与 SYS100 必须来自同一 PLL、相位均为零。MEM 每拍锁存一份 32 位像素及位置、流编号、末字标记和 toggle。后续 SYS 边沿写低半字，再下一边沿写已保存的高半字，可连续接受每个 MEM 周期一个 32 位字。包数据和控制路径必须由真实相关时钟 STA 覆盖，禁止列为异步 false path。

最后一个高半字实际写入后才翻转行完成回执，经两级同步回 MEM。行 CRC 合格并且收到写完回执，两项同时满足才发布行标签。时钟比例异常导致新包与待写高半字重叠时，串行器报告粘滞故障。

媒体复位同时清除 MEM 请求、SYS 串行写状态、PIX 标签与滑动寄存器。RAM 内容不清零；未重新完整校验的行没有有效标签，不能作为视频输出。固定扫描和安全画面使用全局像素复位，持续运行。

`media_reset` 是保持电平接口，必须覆盖 MEM 与 PIX 的两级同步时间。生产恢复控制器保持 64 个 SYS100 周期（640 ns），超过 BASE 最慢像素时钟所需的同步时间；不能替换为单个 SYS 周期的窄脉冲。释放后包 toggle、行写回执和两侧 mailbox 均从同一清零 epoch 开始。

## 行调度及带宽证据

保持四行循环空间和提前两个输出行的预取。双流按 A0、B0、A1、B1 顺序读取，每行五次 64 字突发；近行两流完成后可先发布 partial 标签，完整描述的响应仍单独发送，避免首次 partial 被误认为全部完成。

物理 App 行为模型包含 16 命令、16 quiet 周期和刷新间隙。压缩分支在 MEM50 下完整 HD 扫描通过 5,529,600 个独立邻点比较，0 缺像素；共享 48 kHz 音频输出 799 对样本，0 欠载，并经历 2,395 次刷新。测试入口为 `video_v3_shared_packed_sim.json`。这属于可重复的模型验证，不能替代板上 SDRAM、显示器及音频兼容性验证。

三行缓存与提前一行的独立实验在同一 MEM50 模型中出现 336,465 个缺像素，已否决；没有采用该节省 RAM 的失败方案。

## 字体及数字显示

正常文字和安全文字共享两读口字符表与两读口字形表，各 1,024 字节；每表预期使用一块 RAM9K。原 4,096 字节字体的空行、重复行和高半区空字符无损压缩；`safevision/tools/gen_v3_video_roms.py --check` 对全部原字节展开核对，并检查两个生成资产。

六组十进制状态共用一个逐位 BCD 转换器，60 个像素时钟更新一轮；配置、代际在垂直空白提交，首个可见状态文字前有足够更新时间。字符及图层流水线仍固定四拍。实际 RAM 推断数量、LUT/寄存器和相关时钟裕量，以最终生产源的厂商综合及布局布线报告为准。

应急覆盖层固定红色，HUD 固定使用白/绿/灰，二者透明度只有 0 或 224。`v3_constant224_blend` 对这些常量使用精确真值表，逐通道仍为 `floor((224*foreground+31*background+127)/255)`，透明时精确返回背景；时延保持三拍。OSD 配置透明度 0..255 继续使用通用 `alpha_blend`，四层顺序和功能保留。

`safevision/tools/gen_v3_constant224_tables.py --check` 可从公式重新计算全部11个位平面并只读核对，不重写已测试源码；不带参数输出可复现函数块。独立测试枚举全部65,536个RGB565背景、各前景、两种透明度、valid气泡和复位，共2,097,168次比较。相同目录、相同HD carry32综合设置下，整板资源从22,150 LUT/15,657寄存器变为21,840 LUT/15,560寄存器，RAM52/DSP29不变；两次GUI/CLI源清单、ROM映射及源码稳定性检查正常。该结果仅证明此项优化的收益，整板仍需后续资源优化和布局布线验收。

## 已完成的最终模型验证与静态复查

证据索引 `video_validation.json` 逐项列出17项正常终结测试及31项生产 RTL/资产/厂商依赖 SHA-256。BASE 七完整帧比较 2,150,400 像素，HD 七完整帧比较 6,451,200 像素；另有 HD 1:1 近邻/双线性两帧 1,843,200 像素。正常切换无欠载，CRC 破坏保持安全画面，媒体复位期间扫描连续。

新增转场中点完整帧在 `FADE_FRAMES=2` 测试变体中保持 alpha127，同时读取两幅图并进行双线性缩放，再叠加真实字幕、警示和 HUD。独立参考逐像素核对 BASE 307,200、HD 921,600 个像素，零欠载、零完整性故障，原生仿真均正常结束。默认32帧的精确 alpha 轨迹与最终提交由前述最终回归另行覆盖。初轮 HD 测试结束标记存在空格，严格 runner 拒绝该轮；修正测试标记后在 `v3_video_midfade_final` 重跑两种模式，未把被拒绝记录计为通过。

完整 BASE、HD FIT 与 HD 1:1 坐标扫描另完成 2,895,004 拍检查，逐拍确认包括消隐期在内的 fx/fy 仅为0、85、170，1:1和BASE为0，坐标及有效标签保持固定两拍。公共 FIFO 清理后，共享 MEM50 压力测试在 `v3_video_packed_pressure50_rawrstfinal` 重新正常通过，未沿用清理前的源码指纹。

BASE、HD 动态文字另各检查282,112个完整原字体像素，覆盖四个槽位、全部16种缓存状态、播放/等待/安全状态、两个欠载计数器的全部十六进制数字、全部256种故障码和OSD透明度数字，以及最近邻/双线性、FIT/1:1、Fade、四种轮播周期与亮度符号。参考来自原4,096字节字体和独立语义期望，不读取DUT的字符码、BCD寄存器或动态ROM内容。

独立十进制测试对全部 -256..255 亮度、0..255 代际/对比度及 0..100 音量，直接与原字体计算出的完整字形比较，共 786,432 次；通用缓存用与 640 互质的步长访问全部列，验证跳转、回退和最后一列；打包缓存双相位测试各比较 79,360 邻点，覆盖 tile 511/512、源列639、源行479、重复坐标和复位后重写。移除 CRC 与移除单调坐标护栏的隔离负向副本均正常结束并产生一个预期错误。

色彩处理另穷举全部9位有符号亮度、8位对比度和各RGB通道取值，以独立整数模型核对扩展、符号、饱和和RGB565量化，共8,388,611次比较。FPS测试输入真实帧事件，包含秒边界同拍事件，再用完整数字字形核对实际计数。`safevision/tools/check_v3_video_evidence.py` 对照正常结束证据检查31项当前RTL/资产/厂商依赖指纹，包含共享存储模型实际使用的FIFO IP和SDRAM适配层；修改相关文件后会拒绝继续沿用旧记录。

静态复查确认：相邻行共享一 tile 的情况仅发生在最后行钳位且地址相同；相关 SYS 写的高半字来自已锁存寄存器，不依赖下个 MEM 包；写回执返回前不会发布行；CRC 错误不会发布行；两行提前量只改写已不再显示的四行循环位置；行尾准备发生后仍有足够空白完成预热；垂直回卷预取第0/1行后才启用输出；1:1 视窗的长黑边与 FIT 的重复源坐标均满足单调读取契约。真实相关路径的 setup/hold 仍需最终全板布局布线报告验收。
