# MEM50/+8ns 读回对齐修复 26101702

2026-10-17 COM6 实板逐拍报告 `26101701` 确认：在同一轮 1024 字读取中，前一拍数据比较 P=0 错，当前拍 C=960 错，后一拍 N=960 错。首突发窗口为：T01 有效位 0、数据 A55A3CC3（字0）；T02 有效位 1、数据 A41B3DCB（字1）；T10 是字15，T11 仍为字15。原始 RX 694 字节 SHA-256：`afbb0dcc6ed38a911c479960827f890c02f48b6be8fa812d3aa984d4256df94f`，见 `evidence/v3/board_uart_20261017/m50p8_trace_26101701`。

该证据确定了当前 MEM50MHz/SDRAM+8ns 直接应用接口上的一拍数据/有效信号关系，不证明其他频率/相位采用相同关系，也不代表正式媒体工程的所有故障已排除。

`sdram_app_adapter` 新增 `READ_DATA_LEADS_VALID` 参数，默认 0，保留原先对齐接口的行为。正式 `safevision_v3_top` 为现有 MEM50/+8ns 配置显式设为 1，并将诊断构建 ID 更新为 26101702。参数为 1 时，无条件在每个 MEM 上升沿保存原始 `Sdr_rd_dout`；在 `Sdr_rd_en` 有效边沿将这个前一拍寄存值写入缓存。该寄存器不能由 `Sdr_rd_en` 门控，否则首字仍会丢失。有效信号和返回计数不移动，CRC、缓存批准条件、故障恢复、媒体功能均保留。

原始接口诊断 DIAG10/11 继续观察原始字，属于修复前的采样点；它们不等于适配器修复后提供给 CRC/DMA 的字。不可把 DIAG 首字仍为字1误判为适配器仍错位。

验证模型增加显式 `OUTPUT_VALID_DELAY=1`，仅正式 V3 顶层测试启用，表达实测的“数据先出现、有效信号后一拍”关系。旧模型默认对齐行为保持。独立适配器测试覆盖延迟1/4/20、普通/快速/双银行预取、4096连续读取、稀疏写、字节掩码、邻字保护、跳转、读写反压、预取取消和复位；四组共88项检查通过。正式顶层634次比对、诊断接口65次比对通过。关闭正式顶层的一拍修复后，同一顶层测试正常结束并检出60个数据顺序错误，说明参考模型能发现此次失配。

## 独立实板复核 26101703

`sv_v3_m50p8_fixed` 直接对原厂 IP 应用同样的一拍数据寄存，不经过媒体适配器。默认60000轮，每轮1024个稀疏地址，六种图案各重复10000次，总61440000次字比较；这不是全部2M单元逐一测试。模型核对三轮完整190字节报告，并准确检出第二轮单比特故障，8项检查通过。

该独立探针新冻结源的原生路由和重新导入数据库的四类 Slow/Fast 检查均通过，4924条报告路径无负裕量：setup +1.225ns、hold +0.151ns、recovery +7.472ns、removal +10.056ns。资源1654 LUT、1260 DFF、1 PLL，无片上RAM/DSP。此结果不替代完整 BASE/HD 时序验收。

只有 `artifacts/diagnostics/m50p8_fixed_26101703/probe.index.json` 实际生成后方可下载同目录 `SafeVision_MEM50_P8_FIXED_26101703.bit`。使用 PROGRAM_SRAM，先开 COM6 115200/8N1 再下载/按KEY1；不按CONFIG1。HDMI无图，完整媒体应用源码保留。
