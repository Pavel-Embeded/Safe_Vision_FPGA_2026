# 26101728：银行组对齐与前后掩码补拍

26实板所有完整字App命令数据均匹配其命令地址图案，DM=0总量也正确，而存储仍保持25的6220错误签名。按四拍银行组锁存列、低两位银行地址回绕而不向列进位的模型，精确预测全部六个错误数量、首错地址和首错实际值。例如从19开始写19/20/21时，20可能回到列16的银行0，故地址16读到20。该模型仍是由实际观察支持的契约假设，不是解密厂商IP仿真。

本实验独立命名的sdram_app_adapter_aligned4保留生产逻辑，物理突发起址向下对齐4字。起址低2位决定前置全掩码拍数；真实N字后再全掩码补到4拍倍数。N<=16时物理长度4..20。写缓存读指针减去前置拍数，仅真实区间输出缓存数据及原字节掩码，前后补拍都不更新存储。保留原握手、缓存、读对齐和至少16拍静默，不改频率或时序例外。实验源文件的旧头注沿用基线4..16描述，本段及实际write_span/leading代码说明新增上界20；正式合入时需同步源注释。

使用与26相同的320×12倒序行、1..16变化配额、长暂停、读反压、App观察器和相邻16字保护区。126检查、四场景3840比较、11088 UART字节通过；实际App单次翻位同时被观察器及最终存储检出。六个负控正常结束检错，新增退回未对齐起址会在银行模型中重新产生数据错误。取消掩码的负控检查目标区被破坏；对齐到区域边界后外部保护区可能仍正确，不能只凭保护区断言检测它。

当前生产适配器不改。候选在全部原生时序及约束健康门禁通过、源码和模型/负控绑定提交后才生成，先开COM6再官方SRAM下载，不写Flash。N/W=3840，R/CAP=3856，12轮46272；TX/INPT/DM仍为26被动App错配语义。模型通过后仍须实板验证，不能直接称完整TF卡应用已修复。不上传GitHub。
