# 113 项功能检查点：板级命令 ID 共用

当前113个不同原生正向测试全部正常结束、零失败；28个严格语义负控全部正常结束并检出错误。完整原始日志、源码与输入SHA-256见`evidence/v3/resource_113_20261016/acceptance.json`及`portable_audit.json`。前一版的算术、复位和验证说明见[112项检查点](timing_closure_checkpoint_112.md)，历史目录不能替代当前源码验收。

板级控制现在复用已经验证的7bit命令ID。`v3_user_controls`新增默认0的`BOARD_CATALOG`参数和`catalog_id`输入；普通调用者继续使用原来的名称接口，不需要提供ID。板级顶层显式设1并连接UART目录解析器的同一ID。11个控制ID必须与35命令ROM的排序、名称逐项一致；不认识的命令仍拒绝，所有目标、数值范围、查询、回执及按键优先顺序保持不变。没有增加流水线或改变串口协议。

两套独立等价测试都保留修改前的原控制RTL：普通名称模式和板级ID模式各运行1000000周期，各有5000000次公共输出/数值谓词比较，全部一致。板级测试还混合35个目录名称、不同目标、非法名称/数值、查询与写入、按键、菜单、轮播和复位。破坏BRIGHT的ID绑定被正常检出；原符号边界与写寄存器负控重新执行。24项B链查询和实际UART链回归也重新运行。

这是减少重复译码的实现优化，不是修复串口功能错误。同参数HD映射中控制模块局部LUT从549降到539；整机映射与路由是全局优化，局部节省不保证整机LUT单调下降，最终以原生布局布线资源报告为准。

全部功能、既定时钟和预算保留。正式发布仍要求当前功能证明与所有构建依赖绑定同一Git提交，清洁目录下重建BASE/HD，严格通过Slow/Fast setup、hold、recovery、removal及有效约束门禁后才生成位流。实体显示、音频、SDRAM AC、外部兼容和长稳保持待验。
