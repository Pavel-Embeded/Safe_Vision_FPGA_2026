# 底部中文滚动提示

字幕内容为“安全提示：遇紧急情况，请保持冷静，听从工作人员指挥，并有序撤离。”正常播放和安全画面使用同一条提示。

BASE 的字幕底条位于 x=120 至 631、y=456 至 475，左侧保留运行时间，频谱位于底条上方。正文为白色，底色为黑色，上边缘有一条青色细线。文字从右侧进入，向左移动，完整移出后重新开始。

## 接口与节拍

实现文件为 [v3_scrolling_ticker.v](../../safevision/rtl/video/v3_scrolling_ticker.v)。BASE 26102801 选择 `MESSAGE_CHARS=32`、`EXTERNAL_FONT=0`、`PACKED_EXTERNAL=0`；显示核心的 `SHARED_TICKER` 和 `SHARED_PACKED_FONT` 均为 0。字幕使用独立字库 ROM，频谱沿用自己的系数和显示存储器。

顶层使用最终显示坐标，提前五列读取字模，再用五拍流水线对齐当前像素。原视频链保持 21 拍延迟。底条与上边线按当前输出坐标计算，可见范围由最终坐标和 DE 裁剪。

位置每两个帧起始脉冲增加一个像素。BASE 配置帧率约为 59.965 Hz，移动速度约为 29.982 像素/秒。32 个字格占 512 列，可见字幕区宽 512 列，一个循环经过 1024 个位置，约 34.153 秒。同一帧中的各行使用同一个位置。

模块使用显示域复位。媒体恢复期间，字幕位置继续推进；全局复位清空位置、计数和像素流水线。

## 字库

正文使用 32 个 16×16 字格，以 14 像素字号绘制。ROM 保留全部 8192 个原始像素，包括字格内的空白边缘。每个存储字为一位，地址由 9 位正文列坐标和 4 位字格行坐标拼接而成，使用一块 RAM9K。

ROM 在像素时钟上升沿同步读取，读口本身不加复位；输出有效位和流水线标签单独复位。综合网表检查逐位核对 8192 位内容，并核对实例、端口宽度和存储器初始化数据。

字模读取和 FFT 计算使用各自的 RAM 端口。字幕与音频 PCM 调度之间没有等待握手。顶层像素比较核对完整正文、裁剪边界和原来的频谱画面。

字体为 Noto Sans SC Medium，采用 SIL Open Font License 1.1。字模生成入口为 [build_ticker_font.py](../../safevision/tools/build_ticker_font.py)，字体来源、生成参数和文件校验值见 [字库记录](../../safevision/assets/fonts/v3_ticker16.provenance.json)。字幕文字在构建时生成，随位流保存在 FPGA 字库中。

## 串口观察

| 查询正文 | 回值 |
| --- | --- |
| `B:DIAG=101` | 高 20 位为 `544B1`，低 12 位为当前位置，BASE 范围为 0 至 1023 |

位置和 HDMI 状态通过原有握手邮箱传到系统域。每次诊断回复读取稳定快照。主机用原始发送至 ACK 接收之间的时间窗口核对移动速度、回绕和媒体恢复期间的位置；相邻快照同时计算最短、最长间隔，避免把 USB 回包延迟当成字幕停止。

连续运行检查记录默认参数的写入与回读，并从明确的起点计算运行时长；同时核对原始 ACK、缓存与错误状态，以及自动轮播的 generation 进展。串口记录与实体画面、声音分别验收。

## WAV 校验的综合边界

WAV 解析器的五组拒绝条件分别处理文件头、chunk 格式、PCM 格式、RIFF 尾部和当前状态。生产源码在这五个信号上保留 `keep` 综合属性，让映射工具分别处理它们，再合并当前字节的拒绝结果。

这些属性保持原来的运算表达式、111 位解析上下文、34 位边界上下文、PCM 接收时刻和错误上报时刻。[check_wav_reject_mapping.py](../../safevision/tools/check_wav_reject_mapping.py) 从冻结父版本重建完整解析器，只接受这五处属性差异。原有越界、格式、补齐字节和上下文故障注入继续使用原来的代码位置。

## 音频环缓冲的调度判断

BASE 源码通过 `DIRECT_RING_COMPARE` 启用 [v3_pcm_ring.v](../../safevision/rtl/audio/v3_pcm_ring.v) 的指针比较。读写指针相同时，分区为空；低位相同、额外回绕位相反时，分区已满。四个分区各容纳 16384 组立体声样本，原来的地址布局、预取阈值和 `levels` 占用量输出保持原值。

一次存储器事务结束后才推进对应指针。读请求仅在分区非空时发出，写请求仅在分区非满时发出。复位使两个指针归零，后续串行事务保持占用量处于零至容量之间。这段修改只替换调度条件，不增加请求或 PCM 的时钟延迟。模块默认参数保留原来的差值判断，供历史接口回归使用。

`ring_pointer_compare` 将每拍公开输出与修改前的完整模块对照，并独立检查存储器地址、PCM 内容、回绕、反压和请求中的复位。`audio_system_pointer` 直接运行原有完整音频用例，启用新的生产参数，保留 PCM、48 kHz、generation、报警和媒体复位检查。数学检查入口为 [check_ring_pointer_compare.py](../../safevision/tools/check_ring_pointer_compare.py)，它还核对源码只包含所登记的判断表达式及参数接线改动。

## 媒体文件服务交接

正式配置启用播放器的 `REGISTERED_RESIDENT_READY`。四张图片装载完成后，常驻模式停留在 `S_READY`，直到媒体复位。外部服务就绪信号取自已有的所有权与间隔寄存器，仍保留原来的两拍交接等待；媒体复位会立即撤销就绪信号。

等价测试逐项比较新旧路径的公开接口。另外两项负向控制分别去掉交接间隔和所有权条件，检查提前开放服务的错误能否被发现。

## 图片几何初始化

等比例缩放的分支判定使用 `3×宽 >= 4×高`，与原来的 `480×宽 >= 640×高` 等价。除法分子保持原值。播放器先保存尺寸，再用两拍完成分支选择和初值装载。50 MHz 参考时钟下，这两拍只在 FLEX 图片装载开始时增加 40 ns。

几何临时值使用 23 位。初始分子取 `480×宽` 与 `640×高` 的较小值，在合法尺寸范围内最大为 7,864,320，小于 2²³。此后的有效减法只会减小余量。原始乘积、行坐标和误差寄存器保留原来的位宽。整数域证明与完整图像像素比较分别记录，像素顺序、颜色、方向、比例和后续逐行接口保持原来的约定。

FLEX 的几何工作值由两拍初始化完整覆盖。帧开始时省去三个随后会被覆盖的写操作，保留历史模式的原赋值和两拍初始化节拍。完整父模块只改模块名后作为参考，逐周期核对全部公开输出。

## 宽幅图片的读取进度

源图片按比例缩小时，解码器需要丢弃部分行和列。在这段时间内，TF 卡持续提供字节，输出端可能暂时没有新像素。例如 16384×51、32 位、从下向上存储的 BMP，在首条可见行前需要读取约 3.34 MB 源数据。

播放器仅在真实接收一个字节时更新进度标记。标记经 MEM50 域三级采样后送到写入端。写入端只在当前帧有效、像素 FIFO 和暂存器为空、没有待处理写请求且物理适配器已排空时，使用该进度重新计时。事件与正常存储器读操作重合时，可保留到下一次排空，再使用一次。

待处理写请求、物理写尾和整帧读回仍受原来的期限约束。完成、终止和错误处理优先于进度事件；源字节本身不能使一帧通过校验或提交。`SOURCE_PROGRESS_AWARE` 默认值为 0，正式顶层显式启用。所有新增采样路径继续参加原来的时序检查。
