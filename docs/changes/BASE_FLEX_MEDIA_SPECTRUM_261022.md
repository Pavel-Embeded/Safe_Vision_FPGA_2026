# BASE 任意名称、多尺寸图片和真实频谱整合

状态：开发候选，固件 ID `26102237`。功能证据已形成，整机物理验收、位流和板测应查看最终交付清单；本文件不提前授予这些批准。

## 行为变化

根目录图片不再要求固定 `SVdddd.BMP` 编号。支持合法中文和长文件名；完整名称排序，跳过损坏或不支持的图片，装入前四张有效 BMP。原三/四位编号保持兼容。24 位 BGR 和 32 位 BGRX 的 BI_RGB 图片支持每轴 1–16384，正负高度和行填充均检查，居中等比例适配 BASE 640×480。

伴音优先完整同名主干 WAV，再按轮播槽使用目录顺序的 WAV；不足四路时回到首个 WAV。三位和四位数字名称没有额外配音优先级。图片 CRC 批准后，伴音描述符通过真实 `valid/ready` 接口写入现有音频上下文 RAM。损坏 WAV 会尝试其他候选；无合法候选时播放内置提示音。

生产显示改为 512 点 FFT 的 32 频段音频频谱，包含 Hann 窗、去直流、参考刻度、频率标记、四色频段和峰值保持。输入取实际 HDMI PCM，完整结果在帧边界发布。启动秒计时、亮度/对比度菜单、自适应亮度、缩放、轮播、转场和应急功能继续保留。

完整接口、格式限制及提交时序见 [架构说明](../architecture/flexible-media-and-spectrum.md)。

## 验证规则

保留原 290 个独立正向顶层及 205 个语义负控定义，增加 13 个独立正向顶层和 16 个语义负控，总计 303 / 221。原宽度保护负控更新为包含 FLEX 条件的完整等价保护表达式。冻结参考、实际编译图和所有输入逐一核验；受变更影响的旧测试重新运行，复用的旧记录必须保持输入字节一致。

2026-10-23 的算术与名称存储快照完成 180 个受影响用例的实际原生执行，并重新核验 344 个输入字节未变化的捕获。严格执行器拒绝预先存在的输出目录，11 份拒绝日志保留；这 11 项在全新目录重新执行并通过。另有 19 个旧 B 链测试已由专用执行器通过，汇总器误要求新版结束标记；重新核对其原始检查、精确测试文件的 `$finish` 位置、编译图和输入 SHA 后才纳入验收。原始失败汇总与后续选择凭据分别保存，拒绝、崩溃或未结束的仿真均未计为通过。功能通过不批准后续修改的 RTL，也不批准时序、位流或实板。

图片独立模型检查 8 个完整场景的 2457600 个像素；频谱独立模型以 NumPy FFT 核对全部复数频点。新增的两个只读 oracle 检查器可从任意目录运行，拒绝共同篡改输入和元数据。故意破坏测试必须正常结束且明确检错；编译失败、工具崩溃、超时和 SKIP 均不能计为通过。

片上 RAM 入口队列优化另有强制辅助门禁，不能因为它不改变原 303 / 221 定义就跳过。辅助门禁同时验证默认 1024 字队列与历史公共接口逐拍一致、预索引 512 字队列的扇区信用和真实环缓冲消费、厂商 RAM 几何参数，以及能够正常检错的语义破坏。审计器也用缺失结束标记、替换 mutant、删除冻结参考等反例自检，避免把一份写着 PASS 的元数据误当作完整证明。

原测试名中的 `wave` 是历史接口标识。生产整机测试已改为检查实际频谱像素到最终 RGB 的 21 拍路径，并保留旧波形模块单元兼容测试。完整频谱面板输出另存为仿真图像数据，不能把仿真图像当作实体显示器照片。

## 2026-10-23 BASE 时序修正

BASE 控制域使用已有内存 PLL 的 50 MHz 输出，HD 控制域保持 100 MHz；没有更改 PLL 参数或真实时钟约束。串口、20 ms 消抖、按键菜单、毫秒时间基准、100/200/500 ms 看门狗，以及 60 s 启动和 4.9 s 恢复无进度期限，都显式按实际 SYS_HZ 换算。

板级行完整性观察将事务有效位、地址、数据和帧元数据统一延后一拍；真实 SDRAM 写请求/接受握手不变。生产 packed cache 通过 READ_PIPELINE=1 将读回数据及有效位统一暂存，CRC、写行、字计数和进度使用同一拍；默认参数为0，保留旧接口周期。FLEX 几何计算将宽比较与提交分为两拍，每张最多增加640个REF边沿，最终尺寸、黑边、方向和像素序列不变。

物理源码821535a2900eea9951a8c399a6a7f128bc25f852已经完成实际BASE布局布线和Slow/Fast时序：setup +0.070ns、hold +0.037ns、recovery +3.382ns、removal +0.023ns。原始门禁为native803/base/timing.gate.json，2958条报告路径中无负路径。此结论只批准该物理源码的时序，不能替代正在运行的完整功能回归、位流绑定或真实板测。

## 诊断注入与计数器负控的回归修正

旧诊断测试通过顶层连续赋值别名强制 source_words=153600，该强制也作用于行完整性计数器；新增的冗余 source_first 仍为1，因而触发一致性断言。两个诊断测试现在配对注入 source_first=0，保持这个非零计数场景一致。全部原有协议、范围、媒体复位、背压、事件时间戳及1000个高位别名检查继续执行；两个正向与五项语义负控均正常结束并通过各自预期。生产RTL和断言没有修改。

“frame_counter_one_bit_short”负控原先会被新增的一致性断言提前停止，按验收规则不能算作正常检错。更新后的故障模型仍缩短同一个计数器一位，同时让冗余零标志与这个错误计数器保持一致；原有断言保留，独立公共接口参考发现六次计数回绕错误并正常结束。这个修改仅发生在故意破坏的副本及负控定义中，不进入综合源文件。原始失败日志、原测试文件和原负控定义完整保留。

主矩阵仍为303个独立正向顶层和221个语义负控。最终选择215份当前版本的新执行记录、重新核验309份输入未变的原始记录；主矩阵及上述重试共223次原生执行尝试，其中8次原始失败尝试保留，未计为通过。其余强制辅助验证单独记录。最终是否完成以功能审计和发布清单为准。
