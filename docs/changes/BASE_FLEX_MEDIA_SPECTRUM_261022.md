# BASE 任意名称、多尺寸图片和真实频谱整合

状态：开发候选，固件 ID `26102237`。功能证据已形成，整机物理验收、位流和板测应查看最终交付清单；本文件不提前授予这些批准。

## 行为变化

根目录图片不再要求固定 `SVdddd.BMP` 编号。支持合法中文和长文件名；完整名称排序，跳过损坏或不支持的图片，装入前四张有效 BMP。原三/四位编号保持兼容。24 位 BGR 和 32 位 BGRX 的 BI_RGB 图片支持每轴 1–16384，正负高度和行填充均检查，居中等比例适配 BASE 640×480。

伴音优先完整同名主干 WAV，再按轮播槽使用目录顺序的 WAV；不足四路时回到首个 WAV。三位和四位数字名称没有额外配音优先级。图片 CRC 批准后，伴音描述符通过真实 `valid/ready` 接口写入现有音频上下文 RAM。损坏 WAV 会尝试其他候选；无合法候选时播放内置提示音。

生产显示改为 512 点 FFT 的 32 频段音频频谱，包含 Hann 窗、去直流、参考刻度、频率标记、四色频段和峰值保持。输入取实际 HDMI PCM，完整结果在帧边界发布。启动秒计时、亮度/对比度菜单、自适应亮度、缩放、轮播、转场和应急功能继续保留。

完整接口、格式限制及提交时序见 [架构说明](../architecture/flexible-media-and-spectrum.md)。

## 错误与修正依据

| 触发条件或缺口 | 修正 | 验证入口 |
| --- | --- | --- |
| 任意名称、中文或长文件名无法通过旧编号筛选 | 校验 LFN 序号、校验和及保留字段，保留完整 UTF-16 名称排序；坏 LFN 回到 8.3 别名 | `flexible540`，255 单元共同前缀、中文、emoji、精确 13 单元名称和损坏 LFN |
| 索引找到 WAV，但音频端仍根据数字 cache key 查找，导致实际配音回退 | 图片端提交实际簇号/长度，顶层连接描述符握手，音频端复用上下文 RAM | `flexible_fs550`、`flexible_retry_fs550` 的共享 SPI、四槽帧数据与实际 PCM |
| 精确同名 WAV 与补零数字别名共存 | 精确完整主干优先 | `flexible540` 中同时存在 `SV001.WAV` 与 `SV0001.WAV` |
| 没有完整同名文件，但有三/四位编号看似相同的 WAV | 严格执行用户确认的目录序号回退，禁止数字别名覆盖该规则 | `SV001.BMP` 与不同音色 `SV0001.WAV` 的单元及真实 SPI 反例 |
| 主 WAV 损坏、跨扇区长 JUNK 头或碎片簇链 | 安全收完当前扇区后有界重试，失败游标严格前进，穷尽后提示音 | `wav_retry550`，含 601 字节 JUNK、PCM 循环和全部损坏 |
| 下采样已经画完可见区域，但源图片末尾被截断 | 继续检查未采样尾行，完整文件消费后才完成加载 | `flexible_bmp_bounds551` 及尾流故意破坏控制 |
| 扩展 DIB 头与像素区域重叠 | 要求完整 DIB 位于像素偏移之前，33 位长度和防止地址回绕 | 38 类头边界及 DIB 保护故意破坏控制 |
| 后续目录扇区 CRC/令牌超时，前面已有候选 | `dn_ec` 非零时禁止提交部分目录 | `directory_fault550`，第二扇区真实 SPI 错误及删检查负控 |
| 实体目录序号超过 16 位 | 在回绕前报告 03/33，禁止产生 key=0 | `directory_limit550` 的 65536 项扫描 |
| 合法大图持续加载超过旧总启动/恢复时限 | 预算改为真实进展失活时间，保持独立看门狗和故障优先级 | BASE/HD 的四个 `progress_*561` 顶层及四负控 |
| 给恢复模块中间插入可选端口，导致旧位置式实例的输出连接错位 | 把新增 `progress` 输入追加在全部旧端口之后，生产具名连线不变 | BASE/HD 恢复控制器的原逐拍冻结参考和完整输入故障回归；旧失败日志保留，不计为通过 |
| 新频谱使用原 HUD 不支持的颜色 | 使用已验证的白、青、绿、黄、红精确 alpha 调色板 | 逐像素频谱与生产最终 RGB 比对、palette 故意破坏控制 |
| 新功能引入重复目录元数据与宽数组 mux，超过器件资源 | 去重冻结字段，名称和短名复用同一 RAM，FFT 共用乘法器与四分之一旋转表；比较原生综合策略 | 原始面积报告与最终布局布线，资源压缩不能替代时序批准 |
| 频谱新增存储使器件 RAM 余量不足 | 预索引入口队列改为 512×16 位，保留四路 16384 样本对 SDRAM 环缓冲；按完整扇区占用和保护余量反压，默认实例维持原深度 | 独立入口队列公共接口冻结参考、满反压/环绕/半组复位、四路实际环缓冲/CDC 联测，以及两项正常检错负控 |

## 验证规则

保留原 290 个独立正向顶层及 205 个语义负控定义，增加 13 个独立正向顶层和 16 个语义负控，总计 303 / 221。原宽度保护负控更新为包含 FLEX 条件的完整等价保护表达式。冻结参考、实际编译图和所有输入逐一核验；受变更影响的旧测试重新运行，复用的旧记录必须保持输入字节一致。

图片独立模型检查 8 个完整场景的 2457600 个像素；频谱独立模型以 NumPy FFT 核对全部复数频点。新增的两个只读 oracle 检查器可从任意目录运行，拒绝共同篡改输入和元数据。故意破坏测试必须正常结束且明确检错；编译失败、工具崩溃、超时和 SKIP 均不能计为通过。

片上 RAM 入口队列优化另有强制辅助门禁，不能因为它不改变原 303 / 221 定义就跳过。辅助门禁同时验证默认 1024 字队列与历史公共接口逐拍一致、预索引 512 字队列的扇区信用和真实环缓冲消费、厂商 RAM 几何参数，以及能够正常检错的语义破坏。审计器也用缺失结束标记、替换 mutant、删除冻结参考等反例自检，避免把一份写着 PASS 的元数据误当作完整证明。

原测试名中的 `wave` 是历史接口标识。生产整机测试已改为检查实际频谱像素到最终 RGB 的 21 拍路径，并保留旧波形模块单元兼容测试。完整频谱面板输出另存为仿真图像数据，不能把仿真图像当作实体显示器照片。
