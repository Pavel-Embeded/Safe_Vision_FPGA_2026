# 恢复工具的 Windows 路径兼容修正

整理提交 `d5a2463f` 的 GitHub Actions 运行 `40313312660` 未通过新增的恢复工具测试。原有 5 项和 11 项交付检查已通过，但恢复操作提前报出 `Output resolves through a link`，后续归档检查与完整证据重放尚未执行。

原实现要求输出目录的 `absolute()` 与 `resolve()` 拼写相同。Windows 短路径别名等正常规范化也会改变拼写，因此这个判断不能证明存在链接。本机使用的临时路径没有触发该差异，云端暴露了遗漏。

恢复工具现在逐级检查实际符号链接和目录联接，再规范化输出目录。空目录要求、越界路径拒绝、归档 SHA-256、逐文件校验及拒绝覆盖继续保留。新增正常路径别名和链接父目录两项检查，恢复记录测试共 10 项。

失败的解码日志保存在 [ci_first_failure.json](../../evidence/repository_cleanup_261026/ci_first_failure.json)。本次修改只涉及主机恢复工具、相应测试与记录，生产 RTL、约束和位流保持原字节。新云端结果按实际运行收据记录。
