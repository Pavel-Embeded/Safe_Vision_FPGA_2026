目标固件为 `26102301`。本记录区分源码功能、模型仿真、布局布线、位流以及实板结果；任何一项通过都不自动批准其余项目。最终文件名、批准提交与位流 SHA-256 由实际生成的 `release.index.json` 给出。

## 已复现的故障与修正

旧候选 `26102237` 实际下载后，串口报告四槽已经加载，但行完整性错误计数增加并进入故障状态。该候选的离线通过记录保留用于追溯，明确标记 `BOARD_REJECTED`，不能继续充当成功版本。

BASE 为改善时序而将系统控制时钟改为 50 MHz；32 位像素分组转换为两次 16 位缓存写入的支路却仍使用系统控制时钟，实际也降为 50 MHz。此通路需要独立 100 MHz 写时钟，不能仅靠修改时序约束让它变快。旧模型未使用生产 BASE 的实际时钟比例，原生网表检查也缺少对应的数据路径检查，因此未能提前检出。

生产顶层现在从已有 PLL 引出 100 MHz 写缓存时钟，配套同步释放的媒体复位；BASE 控制与内存仍为 50 MHz。显示核以可选参数和追加在末尾的端口接入写时钟，原接口的默认参数及端口顺序保留。HD 核同步兼容新增接口，避免合并后破坏 HD 的原编译入口。本次交付只批准 BASE。

新增模型直接比较 100:50 MHz 生产比例下的完整写入数据；故意恢复 50:50 MHz 比例必须正常结束并检出数据损坏。全帧读回另核对完整像素、行校验、媒体恢复和新 generation。故意断开外部时钟、禁用参数或使用旧媒体复位的负向测试也必须明确检错，不能把崩溃或超时计作有效负控。

## 保持功能的时序优化

共享文件系统的目录和文件两路地址运算各自保存完整乘积，随后依据同拍寄存的 owner 选择结果并加偏移。运算仍保持两拍有效位和 owner 契约，完整检查 32 位簇号、全部 256 个每簇扇区值、溢出回绕与复位。非法格式仍由原来的格式检查拒绝，不改变目录选图或音频回退规则。

门级检查确认两组独立的 32 位乘积寄存器，选择逻辑位于寄存器之后；最终布局布线使用 29 个 DSP。没有删除 FFT、图片缩放、自动配音、菜单、自适应亮度或故障恢复来换取资源和时序。

原生时钟检查器还修正了两种合法网表语法的解析：带独立位宽声明的总线端口，以及综合工具生成的复位高扇出复制寄存器。它必须逐个检查所有真实复制寄存器的时钟、D、异步复位和时钟报告归属，不允许跳过复制节点。旧解析器拒绝的原始记录保持失败状态；新解析器由正常与故意破坏的网表、时钟报告重新验证，随后完整重跑原生构建。
