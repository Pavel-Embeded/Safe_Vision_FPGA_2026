# BASE 实卡多尺寸图与三位编号兼容修复（2026-10-22）

本轮目标是让用户已经复制到 TF 卡的不同宽高比图片正确播放，并保留现有 BASE 全部功能。用户没有读卡器，因此通过板上 SD SPI 接口只读取得 MBR、FAT32 BPB、八个根目录扇区和媒体文件头；不改卡、不删旧图、不写 Flash。

## 实际问题与修复

旧程序只认可四位编号。实卡新图是 SV001.BMP～SV004.BMP，而音频是 SV0001.WAV～SV0004.WAV。旧程序跳过新图，选中 SV0010～SV0013，并出现四路音频回退。旧图片本身也有多种尺寸，故“屏幕有四张图”不能证明新组已被选中。

生产链在 `fat32_directory_scanner` 的紧凑媒体模式内接受三位或四位十进制编号。三位编号只在内部补零：SV001.BMP 与 SV0001.BMP 归一为同一个0001数字键；四位原规则保留。索引、排序、音频配对、四槽容量、坏文件跳过、CRC、图像缩放及恢复策略沿用原实现。每个目录项开始时清数字寄存器，避免前一四位编号的高位串入三位编号。

通用原始目录模式继续逐字节返回原名。生产模式仍要求 SV 大写前缀、BMP/WAV扩展名及正确空格填充；000/0000会被后级索引拒绝。三位、四位别名属于同一编号，不能用于存放两组不同的同号媒体。

## 验证与证据规则

新增混合名称/排序/WAV配对联合测试及真实八扇区目录重放；故意破坏三位识别、清零和数字顺序的三个变异必须正常结束并报错。所有受物理目录模块改动影响的112个原正向测试和41个原语义负控重新运行，其余原证据仅在所有输入字节和实际编译图一致时复用。最终验收矩阵为290个独立正向顶层与205个正常结束的语义负控。

重新完成 BASE 原约束下的综合、布局布线、Slow/Fast setup/hold/recovery/removal及资源检查后才能生成应用位流。旧批准位流、历史报告和源码保留；不将旧时序结果套用到新RTL。

新版运行时功能ID继续为26102004；准确源码和位流版本用批准提交及SHA-256区分。实板必须回读 IDLOW=00020001、IDHIGH=00040003，确认四槽来自新组；CACHE=F、FAULT=0、WAVFALLBACK=0以及完整性、输出、恢复、视频/音频上下溢计数为0才算通过该轮串口检查。

八组合板测覆盖最近邻/双线性×四种显示几何、32次手动Fade切换与自动轮播，保存原始串口、每条ACK、generation和设置回读。该串口检查不代替实体显示器的方向、黑边、文字/圆形及实际声音确认。

本文件先描述验收规范。是否已经完成、实际位流路径、SHA、资源/时序及板测结果，以同目录发布记录和本轮验收清单为准；未完成步骤不得写成通过。


## 本轮原始时序结果

BASE在原有SDC预算下重新布局布线通过。全局setup/hold WNS为+0.190/+0.024ns，详细recovery/removal最小值为+4.567/+0.036ns；Slow/Fast两角均检查，STNS/HTNS为0。LUT18165/19600，DFF13117/19600，物理RAM60/64，DSP18，PLL3。新RTL只修改生产紧凑目录解析器，未删功能、未改变时钟或约束。

本轮发现外层调度等待1800秒短于原最大图片用例5400秒上限。暂停并替换的只是本任务自己的外层调度；保留正在运行的原生子进程，使用进程句柄记录其真实退出码，原生用例上限、断言、SPI时钟、完整帧比较和源文件保持不变。原生测试正常结束且退出0后才采纳；原调度被终止的记录独立保存在scheduler_recovery，不能被误算作DUT通过。其他排队任务以足够的外层等待继续执行。
