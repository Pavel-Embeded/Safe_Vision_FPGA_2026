# SDRAM 读写对齐排查

2026-10-17 的排查先后使用直接 App 接口、生产适配器和完整媒体链。各层的通过结论分别记录，最终播放验收仍以完整应用为准。

## 直接读回错位

`m50p8_direct_26101612` 首轮 1024 字中有 960 字不符，首地址期望 `A55A3CC3`，实际 `A41B3DCB`。后者对应下一个测试地址的签名，因此继续采集逐拍数据，而没有按随机位翻转处理。

`26101701` 对照前一拍、当前拍和后一拍数据：同轮前一拍比较零错，当前拍和后一拍各 960 错。适配器新增 `READ_DATA_LEADS_VALID`，在有效信号到达前无条件寄存原始读数据。默认参数保留旧对齐行为，生产 MEM50/+8ns 配置显式启用修复。

独立直接探针 `26101703` 随后通过六种图案、60000 轮、61440000 次字比较，零错误。这是 1024 个稀疏地址反复比较，不能描述为逐一遍历全部 2M 单元。

原始说明位于 [docs/v3 归档](../../evidence/debug_history/archives/docs/v3.zip) 的 `sdram_read_alignment_261017.md` 与 `read_alignment_fix_26101702.md`。原始采集见 [board_uart 归档](../../evidence/debug_history/archives/evidence/v3/board_uart_20261017.zip)。

## 生产写入路径

完整应用 `26101714` 仍出现首行 CRC 失败，说明直接探针通过没有覆盖完整数据通路。后续双向探针分别比较“适配器写、直接读”和“直接写、适配器读”，再加入实际媒体的混合突发、行倒序与暂停组合。

诊断 25/26 的写方向累计 23136 次比较有 6220 错，读方向 23136 次比较零错。对齐写探针 28 在相同流量形态、六图案和两个方向下完成 46272 次比较，零错，并保留 2772 字节串口与独立报告核对。生产写逻辑随后采用该方案。

## 非对齐读与后续集成

探针 30 又观察到偏移 1/2/3 的读回 bank 回卷，原理想模型没有覆盖。旧失败报告继续保留，后续读修正、非活动银行保持和 FAT 字节窗口检查逐步进入完整应用。

这些步骤的原文分别位于 docs/v3 归档中的 `adapter_readfix_26101733.md`、`aligned_write_repair_26101729.md`、`bankhold_area_26101735.md` 和 `fat_path_26101736.md`。每个原件的来源路径与 SHA-256 可从 [记录索引](../../evidence/debug_history/index.json) 查询。

2026-10-23 的 packed cache WRITE100 故障属于后续另一处时钟比例问题，见 [独立修正记录](../changes/BASE_WRITE100_REPAIR_261023.md)。当前稳定 BASE 包含最终生产修正，历史单项探针的时序或通过次数不替代其完整资格。
