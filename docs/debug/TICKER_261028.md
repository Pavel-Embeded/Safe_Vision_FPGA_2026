## 查阅与恢复

ZIP 使用按 SHA-256 去重的对象存储。同样的报告只保存一份，`index.json` 保留每个逻辑文件的原路径、大小和 SHA-256。需要恢复原目录时，在项目根目录运行：

```powershell
python -B safevision/tools/ticker_evidence_archive.py --archive artifacts/releases/BASE_26102801/debug/build_history.zip --output D:\Codex\SafeVision_History_Restore
```

输出路径须为新的空目录。恢复工具逐个校验对象并拒绝路径越界。日常复查直接使用 [verify_ticker_flash_delivery261029.py](../../safevision/tools/verify_ticker_flash_delivery261029.py)，无需手工展开全部构建历史。

## 串口采样修正

一次长测在约 57 分钟处因字幕速度判定退出。原始发送间隔为 5335 ms，位置前进 160 像素；本次回包耗时从 15 ms 增至 280 ms。旧主机工具按 ACK 接收时刻计算速度，把回包延迟计入位置采样间隔，产生误报。

修正后，每个 FPGA 快照使用对应原始 TX 至 ACK 的时间窗口。相邻快照的最短、最长间隔分别计算可接受位移，原来的像素容差、串口超时、健康计数、连续监测期限和自动轮播检查保持原值。PowerShell 采集端和 Python 审核端逐字段对照；停住、异常复位、半速、倍速和伪造时间窗口继续被拒绝。

该次中断保留退出码 1。另一次采集运行约 53 分钟后遇到串口关闭，同样保留失败结果及原始字节，见 [usb_interruption274.zip](../../artifacts/releases/BASE_26102801/debug/usb_interruption274.zip)。后续只读采集确认同版固件和四槽状态正常。设备重新枚举的系统时间另存，不能据此替代 FPGA 故障诊断。两小时检查按用户在 2026-10-29 的明确要求取消。最终安装验收保留 40 组配置、8 组缩放、4 档周期，并重新完成 100 次换图、10 次恢复和 60 秒连续观察；中断片段均不拼接进通过记录。
