# 验证与修改记录

## 检查范围

工程共有 713 个 HDL 文件。其中 709 个可读取文件使用 Verilog-2005 编译检查，另有四份厂商受保护 IP，按 SHA-256 核对迁移前后的完整字节并由 TD 加载。262 份仿真清单列出 366 个不同的测试顶层，按清单配置合计展开 389 次，核对模块、端口、参数及层次引用。

功能回归使用独立参考数据核对图像像素、帧与槽号、音频样本、串口内容及恢复状态。正常结束、检查项和错误计数一起参与判断。中途退出、看不到结束标记或出现失败诊断时，运行结果为失败。

| 检查入口 | 验证内容 |
| --- | --- |
| `check_source_tree.py` | 清单、ROM、工程配置、管脚和源文件依赖 |
| `check_verilog.py --compile --elaborate` | Verilog-2005 语法及全部测试顶层展开 |
| `run_v3_sim_flexible.py` | 字幕、任意名称媒体、缩放边界及频谱等回归 |
| `run_v3_sim.py` | 模块、接口、时钟、控制和恢复回归 |
| `run_legacy_b_fourbeat_sim.py` | 旧接口测试，按对应顶层的正常结束与断言日志验收 |
| `run_v3_board.py` | TD 综合、资源检查、实现、时序与位流生成 |
| `tools/host/` | 串口采集、配置与实板操作记录 |

每次仿真使用独立目录，保存输入校验值、编译和展开日志、模拟日志及结果 JSON。GitHub 自动检查编译全部可读取 HDL，并展开各仿真清单的顶层；运行阶段执行字幕 `tb_v3_ticker_clip`、频谱 `tb_v3_spectrum539` 和板级参数 `tb_v3_board_profiles` 三项测试。板级参数测试核对五种配置中的媒体流水、字幕开关和固件标识，共 30 项检查。TD 实现、时序和实板验收由各固件自己的构建记录提供。

GitHub Actions 还运行资源、管脚和命令配置的正反自检。运行页面提供 `source-verification-<提交号>` 下载包，保存编译、展开、三项运行测试及配置自检的记录，保留 30 天。检查失败时也上传已产生的记录，验收时同时查看工作流结果和包内日志。

## 2026-10-30：统一 Verilog

481 个验证文件由 `.sv` 迁移为 `.v`，同时更新清单、工具和测试引用。

带位宽的类型转换改为有明确输入宽度和符号属性的 Verilog 函数；字符串改用定宽字节向量，并保留长度和字符索引的含义。两态检查参数在入口显式处理 X/Z，避免未知值绕过失败检查。循环变量使用局部命名块，并行等待使用命名分支取消，结束报告通过明确的任务或完成信号触发。

仿真失败使用 `[FAIL]` 诊断和 `$finish`，驱动脚本将其判为失败。设计中的正常数据通路保留，厂商 IP 和生成字库按原始校验值核对。

展开检查还发现了旧测试中的接口和依赖问题：

| 问题 | 修正 | 验证入口 |
| --- | --- | --- |
| 恢复控制器的旧位置连接缺少输入 | 改用命名端口，补齐 `progress` | `base_recovery_counter340`、`registered_recovery_reset`、`v3` |
| 共享存储监视器引用了不存在的信号 | 使用实际信号 `svc_d_scan_done` | `shared_storage`、`shared_storage_spi25` |
| 部分视频清单缺少 HD 坐标运算模块 | 补齐 `v3_hd_coord_arith.v` 依赖 | 全部仿真清单展开检查 |
| 像素激励使用不定宽拼接 | 明确写成三路 8 位数据 | `run_legacy_b_fourbeat_sim.py` 中的 `tb_bmp_frame_sink` |
| 负向测试沿用旧版修改锚点 | 对准当前标签与 BMP 长度计算逻辑 | `run_v3_negative_controls.py` 的 7 组控制 |
| 已跟踪的 CRLF 文件被源码绑定误拒绝 | 先核对 Git blob 的原始字节，再使用声明的文本过滤规则 | `test_source_commit_binding.py` 的 4 项正反用例 |
