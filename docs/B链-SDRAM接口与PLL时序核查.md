# B链 · SDRAM接口与PLL时序核查（修正版）

核查日期：2026-10-04；基准：`a1dba93fec8f72e1dd383a2097eb0c5eac96610c`；TD 6.2.168116 / XSim 2018.3 / EG4S20BG256。

**[纠正] PLL 反馈不悬空，USR-6135 和 PHY-5079 已在当前接法的最终构建中消失。发现并修复了回环图案漏检高位地址的 RTL 错误，以及报告选择路径的 fabric 时序问题。SDRAM 数据路径 setup 最坏仍为 −6.826 ns，整板时序未闭合。**

本文件对收到的同名核查稿作证据复核。稿件中的任务安排、所有权建议和“满足两项即可豁免”不是已批准的约束或验收规则。历史 UART / STA 记录保留；当前状态以对应源码和最终构建为准，不上传完整报告、波形、数据库或位流。

## 1. [纠正] 原稿中影响实施的判断

| 原稿判断 | 修正及依据 |
|---|---|
| Clock Summary 中 C0 fanout=0，所以反馈悬空 | 该统计不是反馈连通性证明。wrapper 的 `clkc[0] → clk0_buf → clk0_out → fbclk` 始终有连接；最终 `report_nets` 有 PLL.fbclk 负载及全局 mesh 路由，C0 寄存器端点仍可为 0。外部 `.clk0_out()` 留空不删除 wrapper 内反馈。 |
| 添加 C0 业务负载就能修复补偿 | 之前增加实际寄存器负载仍报 USR-6135。已采用的修正是保持 NORMAL/CLKC0_EXT 参数，将分段显式 BUFG 反馈改为单一 C0 网络，由 TD 路由到全局 mesh；系统 C2 单独使用 BUFG。不能为了增加负载挪用视频/SD/UART 时钟。 |
| `5.000 ns` 是整数，必为占位错误 | 整数/小数格式不证明模型错误；规范限值也可为整数。必须核对具体库、合封器件、工作条件和检查边沿。尚无安路官方勘误或获准替代模型。 |

| 厂商参考报告也为负，因此本工程配置必然正确 | 只能证明问题有先例；不能证明本工程时钟、协议或 corner 已通过。厂商报告也含 fabric 违例，不能作为“全部时序已过”的基准。 |
| 1024 个稀疏地址覆盖全部 bank/row | `ADDR_SHIFT=11` 只改变地址 `[20:11]`，低 11 位固定；按 `row[20:10],bank[9:8],col[7:0]` 映射，bank 和列均未扫描，row 的一位也固定。它是选中地址的混叠检查。 |
| 路径结构、上板结果、厂商解释任选两项即可豁免 | 路径归属和一次板测不能授权豁免。必须有匹配协议/有效窗口的约束依据、完整 setup/hold/corner 审核和工程确认；板测是补充证据。不能通过删除 5 ns、false path 或不分析 C1↔C2 使报告变绿。 |

## 2. [新增] 实际 RTL 修正

### 2.1 高位地址混叠漏检

原 `top_sdram_loopback.pat_of`：

```verilog
{(8'hA5 ^ a[11:4]), (8'h5A ^ a[7:0]), a[11:4], a[3:0]}
```

拼接宽度为 `8+8+8+4=28`，赋给 32 bit 时最高 4 位补零；`a[20:12]` 完全没参与。相隔 4096 word 的地址得到相同图案。因此地址高位断路/混叠时，写侧和比对侧可能同错，依旧 `BAD=0000`。旧 M-11 的连续 4096 word 结果保留，但不能外推为高位地址或全部 DQ 取值覆盖。

新版为四个完整字节：

```verilog
{(8'hA5 ^ a[7:0] ^ a[20:13]),
 (8'h5A ^ a[7:0] ^ a[12:5]),
 (8'h3C ^ a[7:0]),
 (8'hC3 ^ {a[4:0], a[7:5]})}
```

先从第三字节反解 `a[7:0]`，再从第一、第二字节反解 `a[20:13]`、`a[12:5]`，即可恢复全部 21 位。不同合法地址得到不同图案；连续 256 word 时全部 32 个输出位均出现 0 和 1。它提高诊断覆盖，不等同于 walking-1、march、刷新或全部故障模式测试。

### 2.2 UART 报告选择路径

原 `rpt_idx → 宽报告选择器 → UART shifter` 路径余量很薄。加入一个 8 bit 字节缓存及 valid 标记，在 UART 忙时预取并保持；只有 `valid && ready` 才推进报告索引。选择器与发送移位器之间有寄存器边界。

保留顶层端口、默认 4096 word、地址步长、读写命令节奏、初始化/刷新配置、125 MHz/180°、115200 8N1 和正常 **71 Byte** 报告格式。进入 REPORT 后第二个内存上升沿接受首字节，较原来增加一拍；正常接收的数据序列不变。初始化/读等待超时仍终止于 LED 错误态，**原 RTL 没有 UART `ERR=01/02` 错误行**；这里纠正说明，不增加新报文字段。

回环参数使用边界：当前四位十六进制报告和 16 bit BAD 计数应限制 `1 ≤ TEST_WORDS ≤ 65535`；地址不得超出 21 bit，`BURST_N ≥ 1`、`BURST_GAP ≥ 0`、两者之和不超过 256。它不是全容量逐字测试顶层；不能直接设 2M word 后把截断/回绕计数当成验收。

### 2.3 错误比较路径

将 32 bit 逐字比较改为四个 8 bit 比较结果并行寄存，下一拍将其归约成一次错误 word 计数。读返回仍在原 `sdr_rd_en` 拍接收，计数与所对应的地址一起推进；最后一字的比较在进入 REPORT 时完成，报告缓存开始取数前已计入 BAD。完整 UART 和最高 DQ 位注入测试核对了最终计数，防止漏掉最后一个错误。最终默认和稀疏配置的 C1→C1 setup/hold 均为正。

**模型边界**：使用官方 TD PLL 功能模型；因其锁定计数需复位初值，TB 给模型一次初始 reset 脉冲。真实顶层 PLL reset 仍接原常量，未改变产品接法；此仿真不证明芯片上电 AC。TB 的同名 `sdram` 模块仅替代应用侧接口，保持按序延迟返回，不模拟加密控制器、实际 DQ、CAS/刷新、亚稳或 PVT。只按专用脚本编译该 TB，不能把其模拟模块加入 TD 产品源表。

当前完整默认顶层用原 ADC/SDC 与 56 个共享源文件完成 TD 分析、综合、布局布线、`check_design` 和位流生成；未烧录。默认和稀疏配置的最终数据库又在独立 TD 进程中重新导入并重建原 SDC，时序数值一致，4 个时钟及 50/100/125/125 MHz 频率均核对。最终 setup/hold 数值如下：

| 路径范围 | Setup WNS / TNS（ns） | Hold WNS / TNS（ns） |
|---|---:|---:|
| 默认 4096 word，自研 C1→C1 | +0.541 / 0 | +0.137 / 0 |
| 默认整板，包括 SDRAM | **−6.826 / −296.440** | +0.137 / 0 |
| 1024 word / ADDR_SHIFT=11，自研 C1→C1 | +0.723 / 0 | +0.062 / 0 |
| 稀疏配置整板，包括 SDRAM | **−6.826 / −299.435** | +0.062 / 0 |

全局负裕量仍包含 32 个读数据、32 个写输出/三态端点；读最坏 −6.826 ns，写最坏默认 −2.746 ns、稀疏 −2.973 ns。原有时序约束、四个 PLL 的参数/连线、加密控制器和 B/C 产品 RTL 未改；布局变化使旧 SDRAM TNS 和 hold 数值略有变化，不能承诺物理报告逐字不变。USR-6135、PHY-5079 未再出现，C0 反馈路由可追踪到全局 mesh / PLL.fbclk。无 no-clock、无无效约束，但仍有 dummy 节点、I/O delay 缺项及硬核相关异常项；未宣称所有健康检查清零。

## 4. [保留并纠正] SDRAM 的实质风险

125 MHz 周期为 8 ns，180° 相位给相邻有效边沿约 4 ns 名义间隔。读路径包含 `input (hard ip) 5.000 ns`、输入 PAD/寄存器等延时，**还要算发往 SDRAM 的时钟输出延时和采样时钟偏斜**。−6.826 ns 必须按最终 Arrival / Required 完整路径解释，不能只做 `5>4` 比较。

该违例不会必然阻止编译或生成位流，但意味着当前模型下不能证明 SDRAM 数据可靠性。若实际采样窗口不足，可出现读回位错、帧缓存花屏和依赖内存的媒体异常。ROM 测试图等不读 SDRAM 的数据路径不直接经过该 DQ 读写路径。

此前试过多种相位和反馈变体：0° 改善 setup 但新增 hold 违例；90°/270° 仍不闭合；NOCOMP 改变补偿且有无效分析，未采用。没有把降频、改采样边沿、数据/valid 重定时、替换控制器或放宽模型作为本次等价修正发布。后续若采用任何方案，必须一起核对读数据与 valid、写时序、初始化、刷新、带宽及 setup/hold，不能只给读数据加寄存器或遮掉一组路径。
