# 需求、实现、验证与开放事项

本表沿用既有工程 B01–B04 / E01–E05 追踪编号，并补充用户后来明确的四项功能。它区分实现、离线验证和实体观察，不将需求文字当成已完成证据；历史 V2 追踪表保留原日期，本表描述当前 BASE。

| 编号 / 功能 | 当前实现入口 | 离线与物理证据 | 实体验收边界 |
|---|---|---|---|
| B01 本地媒体、四图识别 | `rtl/storage`、`rtl/media`、生产常驻装载链 | SPI/FAT32/目录、坏文件、碎片簇链、BMP/WAV及完整卡/全帧比较 | 四幅现有图片自动轮播和可听音频曾获用户确认；多尺寸替换卡待验 |
| B02 SDRAM与稳定显示 | `sdram_app_adapter`、`rtl/memory`、`v3_video_display_core` | 精确写入采样、行CRC32、读回、反压/刷新及端到端像素；当前BASE全角STA通过 | 新位流CACHE=15/STATUS=7，短时健康计数0；长期稳定性另验 |
| B03 按键/自动切图 | `rtl/control/v3_user_controls.v`、帧提交链 | 去抖/长短按/组合、轮播四档、generation；额外89次手势比较 | KEY2+KEY3菜单、亮度/对比度、KEY3退出直接确认；60秒串口观察含自动提交 |
| B04 HDMI音频 | `rtl/audio`、WAV/PCM环形缓存、顶层PCM/ACR | 48kHz调度、四路容量/回绕、优先级/报警、音量独立对照 | 用户确认能听到声音；不是全部显示器/耳机兼容性结论 |
| E01 转场/画面组织 | `rtl/video` 的缩放、Fade、Alpha、状态/菜单层 | 32帧Fade、四层Alpha、插值、最终RGB独立比较 | 当前菜单画面变化确认；多尺寸实卡几何仍待验 |
| E02 音画联动/可视化 | generation提交、`v3_pcm_waveform`及状态层 | 音画同generation、真实播放后PCM波形、双缓冲与最终RGB | 用户曾确认同功能RTL的青色波形；不宣称FFT或频谱 |
| E03 UART/参数配置 | `v3_uart_link`、命令目录、`v3_user_controls` | 解析/边界/回执/队列/时刻对照；当前40项实板配置测试 | 540个有效ACK/42次健康观察通过；实体亮度/对比度同步变化另有用户确认 |
| E04 故障恢复 | `rtl/safety`、`v3_supervisor`、独立SAFE/ROM报警 | 故障注入、队列、复位/释放/重扫/自检、最多3次重试、超时回SAFE | 大卡重扫可能超出现有4.9秒预算；实体故障长稳不概括为全通过 |
| E05 场景展示/技术交付 | 生产顶层、HUD、完整发布包和文档 | 当前BASE源/证据/STA/位流绑定及复核入口 | 当前HD、长期运行与多设备兼容仍待验，不能宣布整赛题所有验收完成 |
| U01 启动秒计时 | `rtl/video/v3_boot_uptime.v`、CDC邮箱、HUD | 50MHz计秒、BCD、帧边界更新、复位保留测试 | 用户已观察同功能RTL左下计时每秒增加；计量起点为配置完成后逻辑启动 |
| U02 波形替代柱状图 | `rtl/video/v3_pcm_waveform.v`、状态层 | 静音/正弦/方波/斜坡/脉冲/随机及真正输出像素；旧柱关闭 | 用户已看到对应青色波形；窗口128样本，不执行FFT |
| U03 板载亮度/对比度与回显 | `v3_user_controls`、`color_adjust`、`v3_status_layers` | 亮度/对比度范围、按键、显示字符及最终RGB | 修复5cff94e后用户“四步全部正常” |
| U04 多尺寸BMP与缩放 | BMP解析/规范化、输出插值 | 1..1920×1..1080、正负高度、padding、居中、完整帧及最大卡仿真通过 | 测试媒体已生成；用户尚未确认换卡并完成实体多尺寸观察 |
| A01 自动/自适应亮度 | **当前合格BASE没有自动亮度反馈闭环** | 当前链路将配置亮度直接送入`color_adjust`；未发现图像统计/环境光反馈控制及相应验收证据 | 不得以已有手动亮度、自动轮播或参数回显冒充已实现自适应亮度 |

## 开放事项

| ID | 未闭合内容 | 关闭条件 |
|---|---|---|
| OPEN-HD | 当前功能HD布局布线/时序未合格 | 相同功能/正确管脚的完整物理实现、全部角门槛、位流与实板记录 |
| OPEN-MEDIA | 多尺寸实体TF卡显示待验 | 备份原卡后换入给定8个测试媒体；冷启动、4槽/CRC/健康核验、方向/比例/黑边与音频波形实际观察 |
| OPEN-RECOVERY | 最大媒体可能超出4.9秒恢复等待 | 用最大媒体测量并修复/重新验证恢复策略；在此之前保留SAFE/重试边界 |
| OPEN-ADAPTIVE | 自动亮度尚未在当前合格源实现 | 明确图像统计或传感器输入、控制/手动优先级，完成独立模型/全帧/时序/实板验收后发布新位流 |
| OPEN-COMPAT | 多设备HDMI音视频兼容与长期运行 | 记录设备型号、冷启动/断链恢复和明确时长的原始健康/画面/声音证据 |

本次是将已经跑通的BASE准确整理上传，不在上传过程中改动其功能RTL、约束或重新冒用现有位流资格。待验项目继续保留，不从列表删除。
