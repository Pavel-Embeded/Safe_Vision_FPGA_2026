## 0. 一句话现状

## 1. 现象与证据

### 1.1 板级采集（`evidence/board/`）

| 文件 | 内容 | 关键结论 |
|---|---|---|
| `uart_play_status_20261010_1546_boot_to_fault_{hex.txt,bin}` | **7 包（14 行）**，含完整"开机→流式→故障" | **主证据** |
| `uart_play_status_20261010_1503_PH3_fullframe_{hex.txt,bin}` | 1 包，故障态 | `PH=3` 定案 |
| `uart_play_status_20261010_1458_redfault_{hex.txt,bin}` | 1 包，只有第一行 | 早期 |

### 1.2 主证据逐包（189 字节 = `SV-PLAY` 107 + `SV-MEM` 82）

```
包1  ST=8 EC=00 SD=1 CARD=1 CNT=4 RD=0004EEC5 PX=1A542 F=0000 SLOT=0 CRC=0 ED=00
     SV-MEM ID=26101002 PH=0 BAD=00000000 EXP=00000000 GOT=00000000 W=0000CFF7 B=0000
包2  ST=8 EC=00 SD=1 CARD=1 CNT=4 RD=000AA389 PX=38C98 F=0000 SLOT=0 CRC=0 ED=00
     SV-MEM ID=26101002 PH=0 ...                                        W=0001C3A1 B=0000
包3+ ST=A EC=F3 SD=0 CARD=0 CNT=4 RD=000E1036 PX=4B000 F=0000 SLOT=1 CRC=0 ED=01
     SV-MEM ID=26101002 PH=3 BAD=000A0000 EXP=0D968558 GOT=FEA8A821 W=00025800 B=0000
```

**逐项解读**：

| 观测 | 数值 | 含义 |
|---|---|---|
| `RD/PX` 比值 | `0x4EEC5/0x1A542 = 2.998` | ≈3 字节/像素（RGB24→RGB565）⇒ **像素链正确** |
| `W` 轨迹 | 53239 → 115617 → **153600** | **整帧 153600 字全部被接受（100%）** |
| `RD` / `PX` 终值 | `0xE1036`=921654 / `0x4B000`=307200 | **整个 BMP 读完、整帧写完（均 100%）** |
| `PH` | **3** | `integrity_fault`：整帧读回校验失败 |
| `EC` | **F3** | `bmp_frame_sink` 的"读回屏障失败"码 |
| `BAD` | `0x000A0000` | **正是 `SV_IMG1_BASE`**（槽 1 首块地址） |
| `B` | **0000** | **一块都没通过** ⇒ 系统性失败，非随机损坏 |

**故障时序**：写入完整跑完（`W=153600`）**之后**才校验失败 ⇒ **故障点在"读回"这一步，不在写入**。

### 1.3 红框是怎么来的（两个驱动源，同一次失败）

```verilog
// safevision_top.v:576
storage_fault_mem <= memory_error || adapter_fault
                  || (STORAGE_INTEGRITY && (integrity_fault || playback_fault))
                  || swap_fault_latched || fb_wr_error || (sk_ec != 0);
```
1. `integrity_fault`（即 `PH=3`）
2. **`sk_ec = 0xF3`** —— 由 `bmp_frame_sink.v:308`
   `if (REQUIRE_READBACK && verify_done && !verify_pass) err_code<=8'hF3`
   产生，`REQUIRE_READBACK = STORAGE_INTEGRITY`

⇒ 两者是**同一个根事件的两种报法**。`storage_fault_mem` 又驱动 `board_display_guard`
把安全画面切成 `warning_level=2`（**红框闪烁**）。

## 2. 已排除项（都有可复现证据，**别再重复查**）

| # | 假设 | 结论 | 证据 |
|---|---|---|---|
| 1 | 卡路径没就绪（`t_card=0`） | ❌ 排除 | `RD/PX/W` 全部 100%。`SD=0 CARD=0` 是**故障后的实时状态位**，不能反推"卡没起来" |
| 2 | 媒体故障（`pl_state==10`） | ❌ 排除 | `ST=8` 是流式，而 `S_ERROR = 4'd10` |
| 3 | `frame_fault` / `swap_error` | ❌ 排除 | `led[3]=1` 要求这两个都为 0 |
| 4 | `fb_wr_error`（回落写入器） | ❌ 排除 | `fb_start` 写在 `if(card_mode\|\|fb_submitted)…else` 的 **else 里**，`card_mode` 复位=1 且 `STORAGE_INTEGRITY=1` 时永不为 0 ⇒ 回落**从不启动** |
| 5 | 刷新宏默认 125 MHz ⇒ 刷新慢 3 倍 ⇒ 丢数据 | ❌ 排除 | `board_sources.list` 第 2 行是 `safevision_top.v`、第 7 行才是 `global_def.v` ⇒ `ifndef` 取 40 MHz 覆盖值；**且**即使没覆盖，`SELF_REFRESH_INTERVAL`≈48.8 µs，**远低于 SDRAM 64 ms 数据保持期** |
| 6 | `capture` 少收一个字（off-by-one） | ❌ 排除 | `memory_arbiter.v:289` 的 `sd_ack` 是**授权拍的 1 拍脉冲**，数据 `sd_rdata_valid` 经 `response_fire` 在 ≥2 拍后才来，**不可能同拍** |
| 7 | 校验器逻辑错（缩小几何掩盖） | ❌ 排除 | 见 §3.1/§3.2 |
| 8 | 适配器预读路径错 | ❌ 排除 | 见 §3.3 |
| 9 | 地址口径不一致 | ❌ 排除 | `mem_ctrl.v:63` `assign sdram_addr = {2'b00, addr[31:2]}`（字节→字）；写 `App_wr_addr<=wbase[20:0]+wi` 与读 `App_rd_addr<=rfbase[20:0]+rcmd_i` **同为字地址、同一算法** |

## 3. 离线复现与证明（**本机 ModelSim 可跑，不需要板子**）

> 关键发现：**队友的 XSim TB 其实都是纯 SystemVerilog**，没有 XSim 专有语法，
> **可以直接用 ModelSim 跑**。命令见下。

### 3.1 队友的完整性 TB —— 直接跑通

```bash
export PATH="$PATH:/d/modeltech64_10.7/win64"; SV=<repo>/safevision
vlog -sv +incdir+$SV/rtl/include \
     $SV/rtl/memory/frame_integrity_guard.v \
     $SV/rtl/memory/video_read_dma_checked.v \
     $SV/verification/unit/tb_frame_integrity.sv
vsim -c -do "run -all; quit -f" work.tb_frame_integrity
```
结果：`complete top/bottom image in either slot verifies` / `CRC32 matches independent zlib reference`
/ `readback corruption rejects publication` 等**全 PASS**。

### 3.2 ★ 真几何 TB（我新写，已收进仓库）

上面的 TB 用的是**缩小几何**（`WORDS=128, ROW_WORDS=64, BLOCKS=2`），
而板上是 **153600 / 320 / 2400**。新增回归：
**`safevision/verification/unit/tb_frame_integrity_fullgeom.sv`**

```bash
vlog -sv +incdir+$SV/rtl/include $SV/rtl/memory/frame_integrity_guard.v \
     $SV/verification/unit/tb_frame_integrity_fullgeom.sv
vsim -c -do "run -all; quit -f" work.tb_fullgeom
```
结果（理想存储）：
```
verify_pass = 1 | checked_blocks = 2400/2400 | fault = 0 | RESULT: 0 error(s)
```
⇒ **guard 在真实几何下 100% 正确**（含 bottom-up 的 `-ROW_WORDS*8+4` 地址回卷、2400 块全过）。

### 3.3 适配器预读路径（板级配置）

⚠ **坑**：`tb_sdram_app_adapter_streaming` 的 `PREFETCH_READ` **默认是 0**，
直接跑等于**没测预读**（板级是 1）。必须用 `-g` 覆盖：

```bash
vsim -c -quiet -gPREFETCH_READ=1 -gFAST_READ=1 -gRD_LAT=11 \
     -do "run -all; quit -f" work.tb_sdram_app_adapter_streaming
```
结果：**22 checks / 0 errors**，含 `4096 continuous reads match independent address/data scoreboard`、
`read prefetch is in flight with a partially drained previous bank`、`write invalidates a prefetched read cache`。

**⇒ 结论：guard + adapter + 地址口径 全部逻辑正确。板上"读回不一致"只能是真实 SDRAM 的往返问题。**

## 5. 当前最重要的未知（**下一步就查这个**）

> **"真实 SDRAM 的写→读往返，数据到底一致不一致？"**

**推荐路径（按优先级）**：

1. **烧 `board_verify_fbk`（强制回落彩条）** —— 最省事、最直接。
   彩条图案**片上生成**（不经过 SD 卡 / FAT32 / FIFO），写进 SDRAM 槽 0 再由显示读回；
   这条路径 **2026-10-05 曾在板上点亮过**，是已知可用的参照。
   - 彩条正常 ⇒ SDRAM 往返好 ⇒ 问题在**卡路径的数据**（FIFO / 行序桥 / 打包）
   - 花屏/白屏 ⇒ SDRAM 往返真坏 ⇒ 查 **SDRAM 时钟相位（40 MHz + 10 ns 偏移）**、刷新、DQ 引脚

2. **若 1 无法执行**：做一个"**串口报读回第一个字**"的位流 —— 让 guard 在失败时把
   `rd_data` 的首字报出来（`D0=xxxxxxxx`）。不用看屏幕也能知道 SDRAM 读回了什么。
   实现点：`frame_integrity_guard` 增加一个 `first_word` 寄存器（在 `capture` 第一次时锁存），
   顶层接到 `SV-MEM` 行的新字段（`RPT_LEN` 189 → 201，同步改 `tb_safevision_top.sv`）。

3. **若怀疑相位**：把 `ip/pll/sv_board_memory_pll.v` 的 SDRAM 相位（`CLKC2_CPHASE=9`，10 ns）
   改成 0 或其它值做 A/B。**注意**：队友文档称已用 TD `derive_clocks` 核实过 10 ns。

## 6. 踩坑清单（**先读，能省一整轮**）

1. **烧写是 TD GUI 手动步骤，无 CLI 通路**。下载器是 **BitWriter**，`Mode` 下拉有
   `PROGRAM_SRAM`（下到 SRAM，断电丢）/ **`PROGRAM_FLASH`**（烧配置 Flash）/
   `VERIFY_SRAM` / `FLASH_READ` / `ERASE_FLASH` 等。
   ★ 日志出现 `PROGRAM_SRAM success !` + `Downloading succeeded!` **才是真成功**。
2. **板子有配置 Flash（W25Q）+ `FPGA_M0/M1` 配置模式引脚 + `FPGA_PROGRAM_B`（CONFIG1 按钮）**
   （从 `3_原理图/开发板原理图/3_Power_and_Config.pdf` 文字层挖出）。
   ⇒ **断电或按 CONFIG1 会从 Flash 重载**；只下 SRAM 留不住。要长期生效得走 `PROGRAM_FLASH`。
3. **确认位流真换上去**：看串口整包第一个词（§4 的三种抬头）。**不要靠"屏幕有没有变"判断。**
4. **TD 控制台日志是 UTF-16**：`grep` 直接搜会漏，必须先 `tr -d '\000'`。
   路径：`<RunDir>/base.console.log`（注意在 `base/` 的**上一层**）。
5. **`tb_sdram_app_adapter_streaming` 的 `PREFETCH_READ` 默认 0** ⇒ 直接跑**没测预读**，
   必须 `vsim -gPREFETCH_READ=1 -gFAST_READ=1 -gRD_LAT=11`。
6. **队友的 XSim TB 其实是纯 SV，ModelSim 能跑**（见 §3），不必因为没有 XSim 就放弃验证。
7. **`tb_frame_integrity.sv` 用缩小几何** ⇒ 用 `tb_frame_integrity_fullgeom.sv`（§3.2）补真几何。
8. **`frame_integrity_guard.fault` 是 sticky**（`if(frame_begin && !fault)`，只有复位清）
   ⇒ 故障后**必须按 KEY1**，按 KEY2 无效。
9. **`signatures` RAM 无复位**（注释写明 "No RAM reset"）⇒ 未写入的条目是上电垃圾。
10. **别用 `EXP`/`GOT` 反推**：我把它们和**我生成的 4 张测试图的全部 19200 个块**比对，
    **一个都没命中** ⇒ **卡上索引到的第 0 幅很可能不是 `SV0001.BMP`**（用户卡里应有别的图）。
    要反推必须先拿到**卡根目录的真实文件列表**。
11. **`docs/B链-方案A-续做入口.md:192`** 写明："烧写是刻意手动步骤，TD GUI 下载器；无 CLI 通路"。
