## 一、最终定位：**存储器时钟档是根因**

### 1. 现象与排除过程（按时间）

| 阶段 | 做法 | 结果 |
|---|---|---|
| 读回校验 | 板上 `BAD=<槽基址>`、`EXP/GOT=FFFFFFFF` | 读回**处处全 1** |
| 关完整性（`SAFEVISION_DIAG_NO_INTEGRITY`） | 走旧路径（未校验 DMA） | **白屏**，但报文健康（`EC=00 F=0001 CRC=1`），LED 全亮 |
| 字探针 v2/v3/v4 | 直比原始读回字 + 反向校验 + 坏块计数 | 坏块 **2400/2400**；`adapter_fault=0 memory_error=0`；无任何故障标志 |
| 40MHz 下改 `Clk_sft` 相位（144°→173°/187°） | `SV-M172`/`SV-M187` | **仍白屏** ⇒ 相位（在 40MHz 下）不是根因 |
| 去掉 guard + 提高时钟 | `SV-100M`（100MHz + 精确 180°） | **图像出现了（内容正确！）**，但有撕裂 ⇒ **写侧正常、读侧临界** |
| 相位细扫（100MHz） | 2/5/8/1ns | 边界余量 **2ns 最好（-4.787ns）**；8ns 已测无效 |

### 2. 根因链

1. **SDRAM IP（`EG_PHY_SDRAM_2M_32` 封装内硬核）只在高速时钟下工作**：
   所有验证过能工作的配置都是 **125MHz** —— 厂商例程 `lab_ex4_tf` 的 `sys_pll`、
   仓库里上板跑通过的 SDRAM 回环自检 `top_sdram_loopback`、以及 d28（2026-10-06，
   唯一验证过能出图的一版）。40MHz / 50MHz 全部失败。
   （IP 内部逻辑加密，`pragma protect AES128-CBC`，只能实测。）
2. **当初为什么把存储器时钟降到 40MHz**：`frame_integrity_guard` 的**写入侧跟踪**是
   MEM 域最差路径 ——
   ```
   Begin: integrity/source_words_reg[11].clk
   End  : integrity/source_words_reg[27].ce
   Data Path Delay 14.683ns, Logic Level 12   ⇒ MEM 域 Fmax 仅 66.8MHz
   ```
   而 `STORAGE_INTEGRITY=0` 时这条跟踪**毫无用处**。
3. **去掉 guard 后** MEM 域 Fmax 升到 **113.7MHz**；100MHz 档我们的逻辑余量 **+0.769ns** ✓
   （125MHz 档差 0.085ns，门限仍拒；111MHz 放置后也被拒）。
4. 125MHz 档剩下的负路径**全在 SDRAM 硬核内部**
   （`memory_ip/u2_ram/... → memory_ip/sdram.dq`，Logic Level 0~1、纯 PAD/cell 延迟）
   ⇒ **改 RTL 动不了**，正是 `-ExperimentalSdramBitgen`（"allows only classified
   SDRAM-boundary setup failures"）存在的理由，厂商设计里同样存在。

## 二、本轮改了什么（源码）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `platform/.../project/board_verify/td_flow.tcl` | **修 `-define` 透传**：TD 的 `read_hdl` **只应用第一个 `-define`**，写成 `-define A -define B` 时第二个被静默丢弃；改成空格分隔单字符串 + 硬断言 | 此前 `diag3`/`fbk`/`nointg`/`nointg2` 等"诊断位流"**全都等于正常版**（资源逐项相同），串口抬头当然仍是 `SV-PLAY` |
| 同上 | 把"必须存在 32 位 `source_crc`"的断言改为**按条件跳过** | `STORAGE_INTEGRITY=0` 时 CRC 链是死逻辑、被综合优化掉 ⇒ 断言失败、构建被挡死。**这也是"关完整性看能不能出图"这个二分从没跑成的原因之一** |
| `rtl/safevision_top/safevision_top.v` | 新增统一宏 `SAFEVISION_MEM_CLK_HZ`，同时喂 `SAFEVISION_SDRAM_CLK_HZ`（给 `global_def.v` 算刷新）与模块参数 `MEM_CLK_HZ`（**决定 UART 波特率分频**、sink/guard 超时） | 改时钟却忘了 `MEM_CLK_HZ` ⇒ 波特率偏 ⇒ **串口全是乱码**（本轮踩过两次） |
| 同上 | 新增 `SAFEVISION_DIAG_NO_GUARD`：guard **整块不例化**、输出置 0 | 把 MEM 域让出来给高频时钟 |
| `ip/pll/sv_board_memory_pll.v` | 把 `CLKC1/CLKC2` 的 DIV/CPHASE 参数化，新增 `MEM125/MEM111/MEM100/MEM100P2/P1/P0/MEM62/MEM180/MEM187/MEM172` 各档 | 相位公式：`phase_ns = ((CPHASE-(DIV-1)) mod DIV) × 1ns`（VCO=1GHz ⇒ 步进恰 1ns，已实测反验） |
| `rtl/sdram_app_adapter.v` | `addr==rexp` / `addr==wnext` 比较器**由 32 位缩到 21 位**（21 位 = SDRAM 容量 `ADDR_WIDTH=21`，**语义完全等价**） | 125MHz 档非 SDRAM 余量 **-0.796 → -0.085ns**；100MHz 档 **+0.63 → +0.769ns** |
| `rtl/memory/frame_integrity_guard.v` | 新增诊断段（`SAFEVISION_DIAG_WORDPROBE`）：反向校验、失败块原始读回字、坏块总数 `fail_cnt`、`last_read_word` | 用于"读回全 1"的定性 |

**默认位流不受影响**：所有改动都在 `ifdef` 内，或对默认档语义等价（如 21 位比较器）。

## 三、当前状态与下一步

- **写侧完全正常**：报文 `EC=00`、`CRC=1`、`F` 递增、`CUR` 递增、`SLOT` 在 0/1 交替
  ⇒ SD 卡→写→校验→发布一路推进。
- **读侧临界**：同一份配置两次结果不同（一次看到卡里的图、一次白屏）⇒ 时序余量问题，不是逻辑错。
- **下一步**：把 `Clk_sft` 相移往小扫（`SV-P2NS` 2ns 是最优点，尚未上板），
  若稳定则把完整性校验以"不伤 MEM 时序"的方式重新引入；若相位无效则转"换帧/扫描同步"方向。
- **暂不可产出**：125MHz（差 0.085ns）、111MHz（放置后仍被拒）。

1. **位流路径与文件名必须全 ASCII** —— 安路 BitWriter 不接受中文路径。
   位流统一放 `code_review_pack_20261010/bitstream/flash_me/`（纯 ASCII），
   文件名形如 `序号_<抬头>_<配置>_<备注>.bit`。

   文件名带抬头 + **每次烧完先核对抬头**。
3. `code_review_pack_20261010/` 不进 Git（`.gitignore` 是白名单：只跟踪
   `docs/`、`safevision/`、`evidence/`）。
