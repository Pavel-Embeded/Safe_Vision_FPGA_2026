# 说明与调试记录的写法

说明写给接手开发、复测和使用板卡的人。先写结果，再给影响判断的条件和证据。模块说明使用端口、时钟、复位、握手和延迟解释行为；故障记录写明如何触发、实际观察到什么、改在哪里、验证了哪些情况。

## 保留能复核的细节

固件 ID、源码提交、工具版本、位流哈希、输入文件和原始日志路径随结果登记。测试数量保留计数口径，例如独立 top 数与包含别名的记录数分开。失败、超时、工具崩溃和未执行项都按原结果写，后续通过另记一次。

串口能证明报文内容、状态和计数，实体画面与声音由实际观察确认。用户反馈注明收到日期和反馈范围，未取得的测量值留空。

## 句子与版式

直接说明对象和动作，删去寒暄、反复强调、邀约式结尾和空泛评价。标题用模块、现象或操作命名。并列参数适合用表，操作适合用步骤；其余内容写成完整段落。

保留必要的技术区别，例如 valid 与 ready、发出请求与返回数据、模型通过与实板通过。强调格式只用于确有必要的提醒，状态不要靠星号或颜色猜。

## 修改已有说明

按项目采用的 Humanizer 文字规则复核。编辑说明时保留代码示例、命令、路径、元数据、链接目标和技术数据。历史记录继续使用对应版本的结论；发现旧文案与当前实现不一致时，说明差异与适用版本。
