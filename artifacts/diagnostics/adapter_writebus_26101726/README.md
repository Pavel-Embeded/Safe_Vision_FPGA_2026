# 26101726：控制器前的App写数据观察

25在混合突发、倒序行和长暂停下稳定重现写错：六写轮23136比较6220错误，六读轮23136比较零错误。首个地址16读取到地址20的可逆图案。尚不能据此断定是适配器缓冲还是控制器内部映射。

本实验保持25的所有请求、地址、模式、暂停和生产适配器，增加被动三级比较流水：实际App_wr_en接受边沿采集地址/数据/图案模式，下一拍独立计算期望，再比较并锁存首错。只检查目标范围内DM=0的完整字命令；不检查掩码补拍或内部物理更新，不由零错误单独证明地址完整性。

231字节格式长度保持不变，TX/INPT重新定义为首个错配的实际/期望App数据，没有错配则均零。DM低位表示观察到数据错配，次低位表示App DM=0命令总数与3856不一致；其余位零。CNT仍为实际观察的DM=0命令计数。BAD/BAD0仍是后续实际内存读回检查。若数据错配先在App端出现，应查适配器缓存/时序；若没有数据错配，仍需核查地址、掩码意图和控制器，不能仅凭零标志排除全部适配器错误。

126模型检查、四场景3840逐字比较、11088 UART字节通过。第四场景仅在地址5的一个真实App接受边沿翻转一位，App传感器和最终存储读回同时且只检测这一字。关闭传感器的语义负控正常结束2错误，证明诊断未接空。另有旧2拍、取消补拍掩码、取消倒序和取消长暂停四个负控，均须正常完成检错。首次断言在UART帧结束后读取已被下一ROUND清零的观察状态，错误日志保留，修正断言采样窗口后重跑通过；不把原失败改写为通过。

模型不模拟厂商加密控制器或BRAM物理行为。原生两次最终STA的全部类型及必需约束健康检查通过，且绑定提交/输入/证明/工具哈希后才生成位流。官方BitWriter只下载SRAM；先打开COM6，临时无HDMI。独立实验不能代替完整应用TF卡显示与音频验收。暂不上传GitHub。
