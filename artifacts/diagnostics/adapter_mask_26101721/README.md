# 26101721：写掩码延后一拍与相邻保护区实板对照

19的实板十二轮数据表明，延长控制器启动复位不能修复写路径。六个适配器写轮次各1024字全错，直接写入/适配器读回六轮各1024字全对。每个失败轮首字保持上一图案，不能据此断言每个失败字的实际值都相同。旧16在KEY1后同一图案通过，存在读取上一轮同图案残留的盲点，不能作为有效写入证据。

本实验保持生产适配器源码不变，仅在独立顶层把适配器输出的四位DQM寄存一拍；直接写入仍使用DM=0。模型明确假定写地址/数据先接受、下一拍掩码决定其字节更新。这是待实板检验的假设，并非厂商加密IP的仿真。模型符合假设不等于板子已修好。

每轮先直接写16个保护字（地址1024..1039，值5A5AA5A5 XOR地址），排空32拍，再写目标1024字；写完读回目标及保护区1040字。六种图案分别测试慢单字节奏的适配器写/直接读，以及16字直接写/适配器读。不能删掉填充掩码，也不能用密集后续写覆盖邻址破坏。

报告N与W仍为1024，R与CAP应为1040。十二轮TOT=12480。TX是本轮第一个保护字5A5AA1A5，INPT是目标图案第一字。物理App接口DM=0的命令计数：奇数轮2064，偶数轮1040；它仅是接口命令观察，不能解释成SDRAM成功更新的字数。全部BAD必须为零，CFG只允许001或002。

模型缩小为64目标字+16保护字，三场景共2880次比较、8316 UART字节核对、97个通过项。奇偶读路径各注入一位错误，并验证准确报告。关闭一拍延迟的负控正常结束22错误；改为两拍延迟的负控正常结束23错误，其中独立的保护区校验明确失败。崩溃、缺结束标记或SKIP均不算负控检测成功。

诊断必须通过两次原生最终STA、所有setup/hold/recovery/removal及必需约束健康检查后生成位流。位流绑定提交、输入哈希、报告、工具与模型/负控证据。官方BitWriter只做JTAG/SRAM下载，串口先打开再烧录；不写Flash。本程序无HDMI，完整应用功能不受源码删减。实际报告另行保存，未获得实板结果前不得宣称此假设成立或整机通过。暂不上传GitHub。
