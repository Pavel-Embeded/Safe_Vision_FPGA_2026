# 26101725：整机流量形态的双向SDRAM诊断

四拍22小诊断全对，但完整BASE23仍首行CRC失败。23四窗口均320字，源与无掩码写数据全零，物理与校验客户端读回含非零；窗口计数不能证明地址唯一和候选关联。本实验不提前认定剩余故障根因，也不改生产适配器。

保留已验证四拍生产适配器、MEM50/+8ns与厂商IP。每轮先写16个相邻保护字，再写3840字（320列×12行），行从高往低，行内从低往高，符合BMP翻行方向。适配器写请求按1..16变化的配额成组，组间512拍暂停，每128字还停50000拍（1ms）。适配器读请求加入短反压与同样的长暂停，检验闲置/刷新附近的行为。奇数轮适配器写/直接读，偶数轮直接写/适配器读，六图案12轮全部独立报告，包括失败轮。

保护区地址3840..3855，值5A5AA5A5 XOR地址。N/W=3840（000F00/0F00），R/CAP=3856（0F10），十二轮TOT=46272（B4C0）。TX首个保护字5A5AAAA5，INPT是地址3520的图案。DQM保持原拍数，不做21的一拍延迟。UART DM=0命令计数每轮3856，不能解释成实际物理成功写入量。失败报告只有首错和总数，不能臆测全部实际值。

模型缩小为64字、16列、每8字停200拍；独立预计算图案逐字核对，独立计数器验证全部倒序输入顺序，监视补齐形态和暂停覆盖。98检查、2880比较、8316 UART字节通过。奇偶方向各注入一位并精确报告。四个语义负控均正常结束：旧2拍255错误，取消补拍掩码26错误，取消倒序2328错误，取消长暂停1错误；分别保留其数据/保护区/顺序/暂停的独立错误证据。模型不模拟厂商加密控制器自刷新或物理电气行为，实际通路仍须实板对照。

生成位流必须通过两份原生最终时序的所有类型和必需约束健康检查，并绑定源码提交、模型/四负控、工具及全部报告哈希。先打开COM6，再由官方BitWriter只下载SRAM，不写Flash。诊断临时无HDMI；完整23应用和不可变发布包保留，不能把该实验通过等同整机通过。暂不上传GitHub。
