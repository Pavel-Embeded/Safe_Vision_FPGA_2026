# 26101716：写入口/物理命令首字记录与双方向诊断

26101715实际报告首轮CFG=001、W/R/CAP均0400、BAD=0400；首错字地址0，期望A55A3CC3、实际00000000。报告已保存到evidence/v3/board_uart_20261017/adapter_path_26101715。该轮用未经修改的生产适配器写、直接对齐读，未经过适配器读缓存，因此至少写入通路有故障；仍不能单凭首字零值认定全部字为零或BRAM/加密IP中某一项已被唯一定位。

本诊断继续保持生产sdram_app_adapter字节不变，默认两轮，第一轮适配器写/直接读，第二轮直接写/适配器读；即使某轮数据出错，仍输出报告并进行下一轮。每轮1024字连续地址、相同地址签名图案，慢写间隔512MEM周期，所有物理突发/掩码及排空规则沿用26101715。跨轮只清适配器控制，不清SDRAM；第二轮使用直接路径重新写入全部测试数据，避免把第一轮坏数据继承到第二轮。

每轮UART报告231字节，首行SVADP26101716，共两份报告。新增一行`TX=xxxxxxxx INPT=xxxxxxxx DM=x CNT=xxxx`：INPT是第一个接受写事务边沿的源数据，TX/DM是第一个进入厂商控制器的App_wr_en边沿上的数据/掩码；CNT统计该轮DM=0的物理写命令数。正确首字应为A55A3CC3、DM=0、CNT=0400。数据不符定位仍由BAD0给出；两个方向各自清首错，累计TOT保留。任意一轮数据或超时失败，最终LED保持错误状态，不能由后一个通过覆盖错误。

理想接口模型覆盖两个方向以及各自一个单字故障，384次比较、24项检查；1386字节的六份UART报告包含真实引脚串行接收解码和独立预计算逐字节比较。验证包含“先坏后好仍判整次失败”“第一轮出错仍完成第二轮”、写输入反压稳定和64次单字掩码补拍。之前26101715模型另有六种图案双向全覆盖。模型不验证真实BRAM宏、厂商加密IP或电气时序。本诊断临时HDMI无图，完整应用保留，不是删减功能的发布版。
