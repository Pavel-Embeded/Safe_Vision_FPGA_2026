# 上板验收步骤

仅使用最终发布索引中两模式均通过严格时序、资源及源码一致性门槛的位流。先核对 bit SHA-256、开发板型号、引脚文件、V3 50 MHz 存储时钟/8ns 移相和官方 HDMI/IP 依赖；不要混用遗留顶层或历史实验位流。

1. SD 卡按支持的 MBR/FAT32 格式准备，根目录至少四张不同编号的图片，例如 `SV0001.BMP`、`SV0002.BMP`、`SV0003.BMP`、`SV0004.BMP`。候选范围为 `SV0001.BMP` 至 `SV9999.BMP`，使用全大写 8.3 短文件名；`0000` 不合法。图片为640×480、24bit、无压缩，正负高度均支持；可放同编号 48kHz/16bit/双声道 PCM WAV，例如 `SV0001.WAV`。坏/缺 WAV 只影响该轨音频。缓存加载/校验成功后图片常驻 SDRAM。
2. 使用厂商下载器写 BASE，接带扬声器的 HDMI 显示器和可靠线缆。读取 UART STATUS/CACHE/ID/FAULT/UNDERFLOW，记录板号、SD型号、显示器型号、位流哈希和日志。断电重启 10 次，检查四图加载及首帧。
3. 检查下一张、启停轮播、四档周期、100 次转场、菜单所有字段、透明字幕、近邻/双线性、亮度/对比度、音量/静音和 LEVEL。音画应按同一 generation 切换。
4. 持续显示 60min、音频 30min，记录期间视频/音频欠载、溢出和 HDMI drop 计数。另换第二台显示器检查音频枚举与实际声音。
5. 检查坏文件跳过、读取错误/CRC错误、按键抖动、拔卡、内存超时和恢复。安全扫描、片上应急图和报警在媒体复位期间持续；恢复失败保持 SAFE，最多三次；不能通过强制屏蔽错误继续播放。
6. 对 HD 重复以上检查。最后运行 24h 长稳并保留串口原始记录与照片/视频，不能只写“肉眼正常”。

没有实体板卡时，上述项目保持待验。仿真能检查协议与数字逻辑，布局布线 STA 能检查建模条件内的时序；它们无法确认电源、PCB/SD卡/线缆/显示器电气与实际时钟误差，因此不能保证首次上板零错误。
